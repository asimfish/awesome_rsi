从目标到经验再到系统

论文版本：Aspire 2608.31111v1、S³Gym 2608.31100v1、HarnessDev 2609.01437v1。联合项目：ByteDance Seed × TokenWave，与高校及其他机构合作。以下数字来自论文正文与表格；未运行论文实验。专题首页 · 论文与中译下载

1. 一句话定位#

这组三篇基准论文分别检验 agent 能否选择有效的学习目标、从交互经验中获得可迁移的策略，以及把改进保存在可运行的 harness 中。Aspire 用六类能力目标和 520 道隐藏专家题考察目标选择；S³Gym 在七个文本游戏中比较经验利用方式；HarnessDev 的 64 次相邻版本切换中，可见反馈与留出集的变化方向仅 34 次一致。它们共同提示：完成更新循环与获得可靠能力提升，需要分别验证。数字来源为 Aspire §3、S³Gym §3、HarnessDev §4.3。

2. 共同问题：改进目标和判断依据由谁提供#

已有自改进工作常从明确任务、固定奖励和现成执行框架出发。在这样的环境里，模型可以优化一个人已定义好的目标。真实部署还要求系统解释模糊需求、判断经验是否有用，并把有效改变保留到下一次任务。这三种能力不能仅凭最终任务得分来区分。

Aspire 隐藏下游评测，让 agent 自行选择数据、更新手段与验证信号。S³Gym 提供可以探索的环境，同时把正式评估放在更严格的条件下。HarnessDev 直接将生成的执行框架作为评测对象，记录冻结版本，再让它执行下游任务。三者分别移动了原先由人固定的一部分边界，但正式测量仍依赖专家题、环境验证器或留出任务。

3. 分工：三个基准不能互相替代#

研究 保留的外部依据 开放给 agent 的选择 核心缺口
Aspire 隐藏的专家评测与基础模型参照 将能力目标转成数据、训练或 harness 修改 自建代理目标可能偏离真实能力
S³Gym 可执行的环境验证器、严格评测条件 自测、自评，以及经验的存储与利用 能辨认成功行为仍可能学不到有效策略
HarnessDev 冻结制品后的留出任务评测 创建并迭代执行框架 开发反馈、运行模型与版本选择可能共同导致误判

这是一套互补的诊断视角。Aspire 的隐藏题成绩不能推出游戏中的经验学习能力，S³Gym 的成绩也不能证明 harness 能跨执行模型迁移。尤其不能把项目页“闭环 RSI”的研究方向当作已实现系统的实证结论。

4. 方法机制：读论文时应追踪哪些变量#

Aspire：目标的具体化。 输入是宽泛的自然语言能力目标，正式下游任务不向 agent 展示。系统允许权重更新与 harness 更新。读实验时应区分生成检查点、得到合格检查点、超过未改进基线，以及达到保留门槛；前一个事件发生不蕴含后一个事件。内部自测分数只说明选定的代理目标被优化，隐藏专家题才回答目标是否选对。

S³Gym：经验的表达与使用。 History ICL 将原始交互历史放回上下文；Summary Memory 把经验压缩为可复用的文字；Training 则通过参数更新改变策略。摘要可能减少冗余，也可能丢掉状态相关的细节。因此“更紧凑的记忆”并不自动等于“更好的记忆”。论文同时报告不同成绩汇总指标；比较时必须保持指标一致。上下文方法与单独的训练实验不应被解读为同预算条件下的统一排名。

HarnessDev：创建、冻结、执行。 创建者从较弱但可运行的初始框架出发，构造完整 harness；演化阶段读取下游反馈并修改它。创建者和执行者是不同角色，固定执行模型的实验用于检查收益对运行模型的依赖。演化结束后，所有正式版本在 630 个 SWE-Pro 留出任务上评测，结果不反馈给创建者，也不参与它的停止和最终版本选择。

5. 关键证据：局部收益能否留下来#

6. 局限与解释边界#

  1. 作者实验范围：HarnessDev 演化评测集中于代码任务，独立留出结果来自 SWE-Pro。创建阶段的多领域覆盖不能充当演化阶段的多领域证据。
  2. 作者实验范围：HarnessDev 报告九条单次演化轨迹，不能把相邻版本当作互相独立的重复实验。53.1% 不能直接推广为所有系统的概率。
  3. 作者结果：S³Gym 的上下文与参数学习路径并非同一模型、同一资源条件下的全面配对比较，不能由此选出通用最优更新方法。
  4. 本专题判断：外部评估仍是三篇研究测量能力变化的依据。隐藏目标、保留验证器与固定留出集降低了部分偏差，但不足以证明开放世界中的长期自我评估已经可靠。
  5. 本专题判断：论文中的模型版本、预算、反馈协议都会影响结果。本专题整理已报告的证据，不对未测试的模型或后续版本做性能承诺。

7. 在本仓库中的位置#

与报告 05：Who Grades the Grader相连：S³Gym 将“自评是否有用”进一步落到未来决策，不能只看自评本身的正确率。

与报告 13：Meta-Harness相连：HarnessDev 提供另一种评测视角，既看框架能否生成，也看冻结后能否泛化及其对执行模型的依赖。

与报告 14：Self-Harness相连：前者将回归验证用于接受修改，HarnessDev 的后验留出测试则揭示没有参与选择的信息如何改变对版本优劣的判断。这两种验证位置应在阅读时区分。

与报告 26：技能进化相连：S³Gym 说明压缩经验可能有益，也可能损失决策所需细节，技能提炼的价值应在后续任务上验证。

与报告 10：汇总洞察相连：这组三篇补充了“锚在哪”的问题。除了外部评估依据，还要追踪 agent 选择什么目标、经验经过何种变换、最终保留哪个版本。专题据此建议采用四列实验记录：内部指标、独立指标、所选版本与执行模型，分别记录收益和退化。
