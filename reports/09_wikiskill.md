# 解读报告 09 · WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution

| 定位 | Skill 进化（文本可变层 RSI）的当前 SOTA：在原始经验与可执行技能之间插入一个**持久知识层（wiki）**，让技能开发建立在跨迭代累积的结构化知识上 |

## 一句话核心主张

现有技能进化方法（EvoSkill、Trace2Skill、SkillOpt）把"学到了什么"散落在优化历史里，无法跨迭代系统复用；WikiSkill 把 agent 工作区分成三层——不可变的原始轨迹（Raw）、**永不回滚的复利知识库（Wiki）**、门控可回滚的技能（Skill）——持续把经验固化进 wiki，让后续技能更新站在越来越扎实的知识上：五基准五模型全面超过现有方法，且消融证明持久知识积累是收益的关键来源。

## 1. 问题：技能进化的"知识散失"

Agent skill 是把领域专业知识（流程、脚本、资源）打包成文件系统模块（SKILL.md + 资源目录）的轻量格式——不动模型参数就能积累专业能力，天然支持渐进披露（progressive disclosure）省上下文。手工编写 skill 要求预判 agent 需要什么，于是近期工作转向**从经验自动进化 skill**：跑训练任务、分析成败轨迹、改 skill。

但这些方法的共同缺陷：**没有把"学到的东西"维护成独立演化的知识表示**。EvoSkill 只留提案+评估结果的累积历史，Trace2Skill 把轨迹教训直接并进 skill 更新，SkillOpt 用被拒编辑反馈+按 epoch 的元指导——洞见全部散落在优化工件里，同一个错误的根因分析每轮重做，被拒绝的方案换个措辞又被提出来。

## 2. 方法：三层架构 + 四组件循环

### 2.1 三层工作区（各层的可变性刻意不同）

| 层 | 目录 | 内容 | 可变性 |
|---|---|---|---|
| Raw | `raw/` | 完整执行轨迹（推理、工具调用、输出、答案） | **不可变**，一次写入 |
| Wiki | `wiki/` | 模式页（`patterns/*.md`：具体失败模式/成功策略+可行对策）、进化日志（`logs.md`）、技能影响追踪（`skill-impact.md`） | **复利，永不重置、永不回滚** |
| Skill | `skills/` | 活跃技能集，每个含 SKILL.md（全文）+ PURPOSE.md（回链到启发它的 wiki 模式） | **可逆**，验证门控 + 回滚 |

`skill-impact.md` 由外层 harness **程序化**写入：每次验证后追加提案元数据、目标技能、统一 diff、验证分、接受/拒绝结果——给 Skill Proposer 一份客观的干预审计线索，避免重复提出已失败的修改。

### 2.2 每轮迭代的四个组件

1. **Inference Agent**：带活跃技能（全文注入 system prompt，消除检索/触发失败的混淆变量）跑训练集 rollout，写不可变轨迹。**训练时禁止访问 wiki**（关键设计，见消融）。
2. **Wiki Maintainer**：对采样的成败轨迹做根因分析，增量式（patch-based）创建/更新模式页，维护 index.md 与 logs.md。每轮更新数量不设上限，由它自行判断。
3. **Skill Proposer**：多轮 ReAct agent——初始只给 wiki 索引、skill-impact 追踪和训练结果摘要（过/不过、预测 vs 真值），**按需**用 read_file 检查具体模式页和原始轨迹，诊断根因后产出**原子提案**（一次只动一个技能：新建或增量编辑）。
4. **Gating & Rollback**：候选技能集在验证集上评估，只有超过历史最优 Rbest 才接受；被拒则技能回滚——**但 wiki 无论结果如何都保留**。

**核心不对称**：技能（干预）被严格门控、可回滚；知识（证据）自由复利、永不回滚。失败的提案本身也变成 wiki 里的知识（"这个方案试过，验证分 0.72，被拒"）。

## 3. 结果

### 3.1 主结果（五基准：LiveMath 数学 / SealQA 搜索 / SpreadSheet 表格 / OfficeQA 长文档 / ALFWorld 具身）

- WikiSkill 在全部五个模型上平均分第一，比各模型下最强的竞争方法高 **3.3-12.0 分**：Gemini-3.5-Flash 平均 68.1%（次优 56.1%）、Qwen-3.6-27B 63.3%（次优 53.3%）。
- 单点提升可以很大：Gemini Flash 在 LiveMath 33.0→72.6%、SpreadSheet 50.5→76.6%；Qwen-27B 在 ALFWorld 52.8→77.6%。
- 现有方法**不稳定**：EvoSkill 把 Qwen-9B 的 LiveMath 提 30 分，却把 Gemma-31B 同基准降 4 分；SkillOpt 把 Gemini Flash 的 SealQA 降 1.2 分。WikiSkill 在绝大多数模型-数据集组合上不劣于无技能基线。

### 3.2 技能进化与模型规模互补（论文最有趣的发现之一）

- **收益随规模递增**：Qwen 家族内 WikiSkill 平均增益 4B +12.3 / 9B +17.5 / 27B +23.9 分（SpreadSheet 上 27B 增益高达 +40.9）——越强的模型越能执行复杂的进化技能。
- **技能可以抵规模**：Qwen-3.5-9B + 技能（47.4%）> Qwen-3.6-27B 无技能（39.4%）。
- 但下限也存在：OfficeQA 的多步搜索工作流对 4B 太难，小模型执行不动反而回落到默认读文档行为，轻微退化。

### 3.3 跨模型迁移：技能是可交易的工件

- **迁移技能常胜过自进化技能**：Qwen-9B 用 27B 进化的技能在 ALFWorld 拿 70.2%（自己的技能只有 63.4%）；小→大迁移也成立（4B 的技能把 Gemma-31B 的 LiveMath 提到 73.1%）。
- 结论：**技能发现与技能执行是两种不同的能力**——自进化通常把两者混在一起，跨模型转移把它们解耦了。更强的源模型不必然产出更好的技能。
- **负迁移的机理**：4B 进化的 SpreadSheet 技能把 Gemini Flash 从 50.5% 打到 18.1%——小模型技能编码了低层 workaround（单行 Python、字符串转换规则），约束了强模型使用端到端脚本；碎片化诊断流程的冗余工具调用耗尽交互预算。技能的可迁移性取决于它捕获的是**通用流程**还是**模型特定补丁**。

### 3.4 消融：wiki 的两个方向性结论（Gemini Flash）

- **Proposer 有 wiki 访问：48.7% → 63.7%（+15.0）**——没有跨迭代持久知识，Proposer 解不开复杂失败模式。这是"持久知识积累是关键"的直接证据。
- **Inference Agent 训练时访问 wiki 反而有害：63.7% → 60.9%**——任务解法从 wiki 直接泄漏，轨迹里看不出技能本身的缺陷，技能开发信号被污染。知识层必须与执行层隔离，才能保住进化信号的纯度。

### 3.5 案例（ALFWorld, Qwen-27B）

迭代 0：Maintainer 记录 take-examine-move 循环模式；Proposer 提出抽象的 goal-directed-action 技能，验证 0.72 被拒，**diff 与拒绝结果存入 skill-impact.md**。迭代 1：Proposer 参照拒绝史，改提具体行动规则的 break-repetition-loop（"绝不把物品放回原处"），验证 0.78 通过。迭代 2-4：新循环变体出现，Maintainer 累积证据，迭代 4 技能再精化（"每种操作每物品只做一次"）。PURPOSE.md 全程记录技能与动机模式的映射。39-52% 的接受更新发生在早期，其余持续到中后期——精化不停止。

## 4. 批判性评价

**贡献扎实**：把"经验→知识→技能"的三级流水线做成显式架构，并用消融证明中间层（知识）不可省略。"证据自由复利、干预严格门控"的不对称设计是方法论上的真创新——它把科学研究的组织方式（实验记录不可变、综述持续更新、结论要过同行评审）搬进了 agent 自改进循环。案例研究里"被拒提案变成知识"正是人类研究者从失败实验中学习的机制。

**评估侧依然是静态的**。验证集全程固定、Rbest 单调爬升——这是六篇里 EvoLM/RQGM/WGtG 批评的标准静态评估器设置。WikiSkill 的基准（数学、表格、具身任务）有客观真值，静态验证集够用；但推广到主观质量域，它会遇到与 DGM 相同的评估器天花板。wiki 永不回滚还引入一个新风险：**知识层污染**——技能门控挡得住坏技能，挡不住 wiki 里积累的错误归因（模式页写错了根因，后续所有提案都被误导）。论文靠"证据条目引用具体轨迹"部分缓解，但没有 wiki 质量的独立审计机制——把 WGtG 的锚定纪律用到知识层是显然的补法。

**严格门控的保守性**：只接受验证分严格提升的提案，排除了"当下中性但为后续铺路"的修改——作者自认这是为公平对比沿用旧标准。这与 DGM 的核心发现（踏脚石常经过性能下跌）直接冲突：WikiSkill 的技能层是纯爬山，探索性全部由 wiki 层的知识积累承担。一个自然的追问：如果技能层也允许 DGM 式档案分支，收益会不会更大？

**与 MOSS 的对照最有张力**。MOSS 论证文本可变层"物理够不着"harness 故障；WikiSkill 恰好证明文本层内部还有大量未挖掘的收益（+23.9 分）且技能可跨模型交易——源码层做不到这一点（MOSS 的补丁绑定具体代码库）。两篇合起来给出完整版图：**结构性故障归源码层，流程性知识归文本层**；文本层的可移植性（技能市场、跨模型复用）是它相对源码层的独立优势，Anthropic 的 skills 生态正在验证这个方向的商业价值。

**全文注入的实验室设定**：技能全文进 system prompt 回避了检索/触发问题——生产环境技能库增长后，检索失败会吃掉一部分论文收益（作者列为局限）。这恰是 MOSS 说的"文本修复随上下文累积而衰减"的另一面。

## 5. 在 RSI 版图中的位置

- Weng 框架对位：3.2 节"文件系统作为持久记忆"的最严格实现——她提的 append-only 日志、结构化知识、按需读取在这里全部落地为 raw/wiki/skills 三层；同时它是"self-improving harness"分类下**记忆分支**（区别于 DGM 的代码分支、EvoLM 的权重分支）的代表作。
- 对小红书六篇的补位：六篇聚焦"评估器进化"，WikiSkill 聚焦"知识沉淀"——两个正交轴。它的验证门控是最朴素的静态评估器，评估侧三篇的全部批评都适用于它；反过来，它的持久知识层恰好是 ECHO/RQGM 缺的东西（那两家的 critic/evaluator 每轮进化但不沉淀结构化知识）。
- 与 Anthropic 文章对读：Anthropic 说 RSI 的最后瓶颈是"品味"（方向感与评估）；WikiSkill 的 wiki 正是品味的可积累形式——什么方案试过、为什么失败、什么模式反复出现。skill 迁移实验（发现与执行解耦）还暗示：品味可以由强模型生产、弱模型消费。
