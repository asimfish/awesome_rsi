## 1. 一句话定位

编码 agent 已能检查仓库、调工具、跑测试、调试、生成补丁，但大多数部署后即静止——而软件开发是动态、反馈丰富的过程：仓库演化、依赖变化、测试失败、修复尝试留下可复用经验。综述给"自进化编码 agent"下了边界定义：**不是**传统编码 agent 加一个学习模块，**也不是**通用自进化 agent 套到代码上，而是"基于此前编码尝试与软件特有反馈更新自身行为或内部组件的 agentic 软件工程系统"——其独特性在于进化发生在**可执行制品**构成的闭环里：单元测试、编译诊断、运行轨迹、静态分析、仓库历史、CI 日志、代码评审都能成为适应的证据。三个正交维度：**进化对象**（框架 / 记忆 / 技能工具 / 模型 / 工作流拓扑）、**进化时间**（任务时 / 任务后 / 阶段式）、**进化证据**（结果 / 环境反馈 / 轨迹）。核心判断：**结果证据支撑选择，环境反馈支撑在线适应，轨迹证据支撑积累**——三者不可互换。最有价值的部分是风险节：一个不可靠的测试结果、噪声轨迹、弱验证器或基准捷径，**不只影响一个补丁，而会被存进记忆、蒸馏成技能、选成工作流、或用来更新模型**——错误被持久化。它是本仓库第三份综述，把镜头收窄到编码域；配套 awesome 列表是与本仓库最接近的同类资源。

## 2. 综述要回答的问题

编码域是 RSI 文献里占比最高的域——DGM、SICA、Meta-Harness、Self-Harness、AutoSaddler、HarnessFix、RHO 全部以编码基准为主战场。为什么？综述的回答是**可执行反馈**：代码能跑、测试能过、编译会报错——这些是免费的、确定性的、即时的监督信号，其他域（写作、研究、对话）没有。

但这引出两个问题：
1. **可执行反馈到底有多可靠？** 测试不完整、编译通过不等于正确、CI 日志有噪声、基准有泄漏——如果 agent 从这些信号里学，学到的是什么？
2. **编码域的自进化能否迁移到其他域？** 如果全部收益来自可执行反馈，非编码域就没有自进化的希望——这是对整个 RSI 议程的挑战。

综述的框架因此围绕"证据"组织：不同证据支撑不同类型的进化，也带来不同类型的风险。

## 4. 三个正交维度拆解

### 维度一 · 进化对象（§3，主分类）

| 对象 | 内容 | 本仓库对应 | 风险等级 |
|---|---|---|---|
| **框架自进化** | 改自身脚手架实现 | SICA、DGM 及后继（报告 07/23）、Meta-Harness（13） | **最高**——"比更轻量的形式引发更强的可靠性担忧" |
| **记忆自进化** | 仓库记忆、issue 解决经验库 | WikiSkill（09）的 wiki 层 | 中——错误归因被持久化 |
| **技能与工具自进化** | 把编码轨迹蒸馏为技能注册表 | 技能进化红海（26）、SkillCommit | 中——技能过时、冗余 |
| **模型自进化** | 用软件演化数据训练策略 | iCoder（19）、Co-Harness（21） | 高——权重不可回滚 |
| **工作流与拓扑自进化** | 多 agent 角色、通信模式、拓扑的进化 | HyperAgents | 高——责任模糊 |

### 维度二 · 进化时间（§4.1）

- **任务时（task-time）**：解题过程中因测试失败/编译错误即时改补丁、改工具用法——最便宜、最不持久；
- **任务后（post-task）**：把结果抽象为记忆/技能/仓库知识——中等；
- **阶段式（stage-wise）**：累积一批验证轨迹后更新模型或组织——最贵、最持久。

三者在持久性与成本上递增。与本调研的免重置/重置式之辨（报告 11）对照：任务时 ≈ intra-episode（CH 的领地），阶段式 ≈ 离线批次（AutoSaddler、Co-Harness 的领地）。

### 维度三 · 进化证据（§4.2）

| 证据 | 内容 | 支撑什么 | 粒度 | 可靠性 |
|---|---|---|---|---|
| **结果证据** | 基准解决率、测试通过率、验证器分、准确-成本-延迟综合效用 | **选择**（SICA/DGM 靠它筛选自改写版本） | 粗 | 受基准泄漏、测试不完整影响 |
| **环境反馈** | 编译诊断、测试日志、运行错误、工具输出 | **在线适应** | 中 | 受工具 bug、沙箱保真度影响 |
| **轨迹证据** | 完整轨迹里成功与失败动作揭示的可复用策略、反复错误、仓库特有实践 | **积累**（跨任务经验/记忆/技能） | 细 | 受噪声、LLM 非确定性影响 |

**核心判断**：三者不可互换——同一个"应该改"的信号在三种证据下是三种不同的监督。用结果证据做积累（把"这次过了"当作"这个策略好"）是常见误用。

## 5. 编码域特有的风险（§6）——全文最有价值的部分

**放大机制**：一个不可靠的测试结果、噪声轨迹、弱验证器或基准特定捷径，不只影响一个补丁，而会被存进记忆、蒸馏成技能、选成工作流、或用来更新模型——**错误被持久化**。这是自进化相对于单次推理的**特有风险**：单次推理错了就错一次，自进化错了会复利。

四组挑战：

1. **可复现性、污染与基准过拟合**：用基准结果选自改写版本的系统对评估噪声与基准泄漏尤其敏感（点名 SICA、DGM）；代码评估本来就有污染问题，未来评估必须区分真提升与记忆化 / 反复调参 / 对公开验证信号的过拟合。——对应 Meta-Harness TB2 搜索集 = 测试集的问题（报告 13 局限 1）。

2. **反馈可靠性、安全与工具依赖**：测试、编译器、CI 日志、生成测试、奖励模型都不完美，依赖它们的系统继承其偏差与盲点；当 agent 修改工具、工作流或自身脚手架时风险尤甚——**误导性反馈塑造的是未来行为而非单次输出**。工具可靠性、沙箱保真度、安全检查是自进化问题的一部分而非实现细节。——对应 EnvHarness 的"环境会说谎"（报告 15 局限 2）。

3. **长期记忆、技能与协调**：经验库、仓库记忆、技能库会过时、冗余、过度仓库特定、被失败轨迹污染；多 agent 与工作流进化增加成本、不稳定与责任模糊。——对应 WikiSkill 的 wiki 污染风险（报告 09 局限 2）、SkillProx 的"删除一等公民"（报告 26）。

4. **超越短基准的评估**：现有评估主要测短时程通过率/解决率，真实软件工程还要可维护性、安全性、可评审性、效率、长期可靠性；现有证据多为域内或近域迁移，**从软件工程反馈学到的进化能否迁移到非编码域基本未探索**。

## 6. 局限

1. **分类学与报告 12 高度同构**：进化对象六类 ≈ TMLR 的 What 维、进化时间三类 ≈ When 维、进化证据 ≈ How 维的输入侧；增量在"编码域实例化"与"证据三分法"，而非新框架。
2. **同样没有锚的理论**：§6 说得很对——错误会被持久化——但对策停在"评估必须区分真提升与过拟合"的呼吁，没有给出 Who Grades the Grader（报告 05）那种"必须外置不进化的锚"的构造性结论，也没有引用锚定纪律这条线。
3. **收录截至 2026 年中**：Meta-Harness、AutoSaddler、HarnessFix、RHO 等 2026 年 6–8 月的 harness 优化工作多数不在正文分类里（配套 awesome 列表在持续补充），而这些恰是编码域自进化最活跃的一支。
4. **可执行反馈的"天然优势"被高估**：综述把可执行反馈当作编码域的独特红利，但 HVTB（报告 27）与 Prime Agent（报告 18）显示可执行反馈同样可被 game——通过测试不等于解决问题；DGM 的伪造日志（报告 07）是最早的例子。红利与风险是同一枚硬币。
5. **"迁移到非编码域"的问题提出了但没回答**：这是对整个 RSI 议程最重要的问题之一，综述只用一句话带过。
6. **无定量元分析**：与 TMLR 综述同样，权威性来自覆盖面。

## 7. 意义与位置

**三综述的分工**（报告 12 / 22 / 28）：TMLR 给单体自进化的四维坐标，Co-Evolution 给多组件互相施压的三阶段，本文给编码域的对象-时间-证据三维——三者合起来，本仓库的每一篇论文都能在至少两张图里找到位置。

**证据三分法是对报告 10 §2 两轴地图的补充**：报告 10 按"改哪里 / 卡哪里"分解，本文加了"**凭什么改**"——结果 / 环境 / 轨迹三种证据的可靠性差异，正是评估器战争（报告 03–06、24–25）的编码域版本。

**对报告 23 桥接史的独立确认**：综述把 SICA 与 DGM 并列为"用结果证据验证自改写"的代表，并把它们列为基准过拟合风险最高的一类——与报告 23"证明门 → 效用门 → 基准门"的三步松弛叙事一致。

**对报告 13–16 harness 工业化四篇**：按本文分类，Meta-Harness / Self-Harness / AutoSaddler 都是"框架自进化 + 阶段式 + 结果证据"——风险最高的格子。它们各自的门控（proposer 隔离、双 split 回归、dev 门）是对本文风险 1 的工程回应。

**对报告 19 iCoder**：iCoder 是"模型自进化 + 阶段式 + 结果证据（verifier）"——本文说这个格子风险高（权重不可回滚），iCoder 的回应是 checkpoint 血统可溯源 + verifier 不许削弱。

**"错误被持久化"是本调研 insight 之一的独立表述**：报告 10 说"评估器塌缩是主要死因"，本文说"错误会被存进记忆、蒸馏成技能、选成工作流"——同一件事的两个视角：前者说锚在哪，后者说没有锚时错误往哪流。

**配套 awesome 列表是本仓库的近邻**：iSEngLab 按进化对象组织论文、覆盖编码域；本仓库按"锚在哪"组织、覆盖 RSI 全谱系（含前史、评估侧、宏观争论）——两者互补，已互相收录。
