## 一句话核心主张

编码 agent 已能检查仓库、调工具、跑测试、调试、生成补丁，但大多数部署后即静止——而软件开发是动态、反馈丰富的过程：仓库演化、依赖变化、测试失败、修复尝试留下可复用经验。综述给"自进化编码 agent"下了边界定义（Table 1）：**不是**传统编码 agent 加一个学习模块，**也不是**通用自进化 agent 套到代码上，而是"基于此前编码尝试与软件特有反馈更新自身行为或内部组件的 agentic 软件工程系统"——其独特性在于进化发生在**可执行制品**构成的闭环里：单元测试、编译诊断、运行轨迹、静态分析、仓库历史、CI 日志、代码评审都能成为适应的证据。

## 三个正交维度

**维度一 · 进化对象（§3，主分类）**：agent 框架自进化（改自身脚手架实现——SICA、DGM 及其后继）、记忆自进化（仓库记忆、issue 解决经验库）、技能与工具自进化（把编码轨迹蒸馏为技能注册表）、模型自进化（用软件演化数据训练策略）、工作流与拓扑自进化（多 agent 角色、通信模式、拓扑的进化）。综述特别指出框架自进化"比更轻量的形式引发更强的可靠性担忧"。

**维度二 · 进化时间（§4.1）**：任务时（task-time，解题过程中因测试失败/编译错误即时改补丁、改工具用法）、任务后（post-task，把结果抽象为记忆/技能/仓库知识）、阶段式（stage-wise，累积一批验证轨迹后更新模型或组织）。三者在持久性与成本上递增。

**维度三 · 进化证据（§4.2）**：结果证据（基准解决率、测试通过率、验证器分、修复成功率或准确-成本-延迟综合效用——粗粒度但提供选择压力，SICA 与 DGM 靠它筛选自改写版本）、环境反馈（编译诊断、测试日志、运行错误、工具输出——引导进行中的适应）、轨迹证据（完整轨迹里成功与失败动作共同揭示的可复用修复策略、反复错误、仓库特有实践——支撑跨任务的经验/记忆/技能积累）。

综述的核心判断：**结果证据支撑选择，环境反馈支撑在线适应，轨迹证据支撑积累**——三者不可互换，同一个"应该改"的信号在三种证据下是三种不同的监督。

## 编码域特有的风险（§6）

综述最有价值的部分是把自进化的风险放大镜对准软件工程：一个不可靠的测试结果、噪声轨迹、弱验证器或基准特定捷径，**不只影响一个补丁，而会被存进记忆、蒸馏成技能、选成工作流、或用来更新模型**——错误被持久化。四组挑战：

1. **可复现性、污染与基准过拟合**：用基准结果选自改写版本的系统对评估噪声与基准泄漏尤其敏感（点名 SICA、DGM）；代码评估本来就有污染问题，未来评估必须区分真提升与记忆化/反复调参/对公开验证信号的过拟合。
2. **反馈可靠性、安全与工具依赖**：测试、编译器、CI 日志、生成测试、奖励模型都不完美，依赖它们的系统继承其偏差与盲点；当 agent 修改工具、工作流或自身脚手架时风险尤甚——误导性反馈塑造的是未来行为而非单次输出。工具可靠性、沙箱保真度、安全检查是自进化问题的一部分而非实现细节。
3. **长期记忆、技能与协调**：经验库、仓库记忆、技能库会过时、冗余、过度仓库特定、被失败轨迹污染；多 agent 与工作流进化增加成本、不稳定与责任模糊。
4. **超越短基准的评估**：现有评估主要测短时程通过率/解决率，真实软件工程还要可维护性、安全性、可评审性、效率、长期可靠性；现有证据多为域内或近域迁移，**从软件工程反馈学到的进化能否迁移到非编码域基本未探索**。

## 局限与批评

1. **分类学与报告 12 高度同构**：进化对象六类 ≈ TMLR 的 What 维、进化时间三类 ≈ When 维、进化证据 ≈ How 维的输入侧；本文的增量在"编码域实例化"与"证据三分法"，而非新框架。
2. **同样没有锚的理论**：§6 说得很对——错误会被持久化——但对策停在"评估必须区分真提升与过拟合"的呼吁，没有给出 Who Grades the Grader（报告 05）那种"必须外置不进化的锚"的构造性结论，也没有引用锚定纪律这条线。
3. **收录截至 2026 年中**：Meta-Harness、AutoSaddler、HarnessFix 等 2026 年 6-8 月的 harness 优化工作多数不在正文分类里（配套 awesome 列表在持续补充），而这些恰是编码域自进化最活跃的一支。
4. **可执行反馈的"天然优势"被高估**：综述把可执行反馈当作编码域的独特红利，但 HVTB（报告 27）与 Prime Agent（报告 18）显示可执行反馈同样可被 game——通过测试不等于解决问题；红利与风险是同一枚硬币。

## 与本调研的连线

1. **三综述的分工**（报告 12 / 22 / 28）：TMLR 给单体自进化的四维坐标，共进化综述给多组件互相施压的三阶段，本文给编码域的对象-时间-证据三维——三者合起来，本仓库的每一篇论文都能在至少两张图里找到位置。
2. **证据三分法是对报告 10 §2 两轴地图的补充**：报告 10 按"改哪里 / 卡哪里"分解，本文加了"凭什么改"——结果 / 环境 / 轨迹三种证据的可靠性差异，正是评估器战争（报告 03-06、24-25）的编码域版本。
3. **对报告 23 桥接史的独立确认**：综述把 SICA 与 DGM 并列为"用结果证据验证自改写"的代表，并把它们列为基准过拟合风险最高的一类——与报告 23"证明门 → 效用门 → 基准门"的三步松弛叙事一致。
4. **配套 awesome 列表是本仓库的近邻**：iSEngLab 按进化对象组织论文、覆盖编码域；本仓库按"锚在哪"组织、覆盖 RSI 全谱系（含前史、评估侧、宏观争论）——两者互补，已互相收录。
