## 1. 一句话定位

DGM 是第一个用前沿模型驱动、带开放式档案搜索的自改写 agent：一个编码 agent 反复修改自己的 Python 代码库（工具、工作流、提示），每个新版本在编码基准上实测，能编译且保留代码编辑能力的版本进档案，档案里任何节点都可能被再次选中当父代。80 轮迭代后，SWE-bench Verified 从 **20.0% 到 50.0%**，Polyglot 从 **14.2% 到 30.7%**（全量口径），追平经核查的开源 SOTA，远超人类打磨一年的 Aider。

对照 Schmidhuber 2003 年的哥德尔机——只有在找到"改写后严格更优"的形式证明时才允许自改写——DGM 做了一次工程史上的关键松弛：**证明换成实验**。这次松弛带来了 2025-2026 年整条 RSI 工程谱系（报告 11、13、14、16、20 都以它为基线或靶子），也把评估器变成了新的单点故障（报告 05）。

## 2. 要解决的问题：手工 agent 设计的天花板与"改进不递归"

论文开篇的诊断有三层：

1. **今天的 AI 系统被人类设计的固定架构框死**。编码 agent 的工具、提示、工作流是人手写的，能力上限等于设计者的巧思。ADAS（Hu et al. 2025）之类的元学习方法能自动搜 agent 设计，但**元 agent 本身是固定的**——下游任务上的提升不会转化为更强的自改写能力，改进不递归。
2. **哥德尔机的证明要求在实践中不可满足**。论文举的例子很具体：一个编码 agent 看起来加更多工具（代码搜索、测试运行器）应该更好，但实际效果高度依赖模型训练与任务语境——为一个环境优化的测试工具可能在另一个环境把 agent 搞糊涂。这种收益无法形式化证明，只能试。
3. **爬山式自改写会被骗**。同期的 SICA（Robeyns et al. 2025，报告 23）也是单 agent 改自己代码，但只从最新版本出发；一次表现下降的改动会让后续改进更难，一次失去代码编辑能力的改动会让系统彻底瘫掉。

DGM 的核心赌注写在正文里："**编码基准上的性能提升即意味着更强的编码能力，从而意味着更强的自改写和自改进能力**"——因为自改写本身就是一个编码任务。这一句是全文的承重墙，也是后来被 Who Grades the Grader 系统性检验的那句话。

## 3. 为什么此前做不通：三种前驱各缺一角

| 前驱 | 有什么 | 缺什么 |
|---|---|---|
| Gödel Machine（2003） | 完全自指的形式框架 | 证明门在现实里永远打不开 |
| ADAS / Meta Agent Search（2024-25） | 自动搜 agent 设计、基准验证 | 元 agent 冻结，改进不回流到搜索者自身 |
| Gödel Agent（2024，报告 23） | LLM 运行时改自身逻辑 | 单链、无档案、无经验验证纪律 |
| SICA（2025，报告 23） | 单 agent 改自己代码 + 基准/成本/时间效用 | 爬山式，只从最新版出发，无法从失败节点绕行 |

DGM 的组合是：**取 Gödel Machine 的自指目标、取 ADAS 的基准验证、取 SICA 的编码域、加上前三者都没有的开放式档案**。论文在 §2 明确说，与 SICA / Gödel Agent / STOP 的主要区别就是"开放式探索环，鼓励超越即时收益的自改写，避免停滞在次优状态"。

## 4. DGM 的机制

### 4.1 自指自改进：把自改写定义为一个编码任务

系统只从**一个**初始 agent 出发：冻结的前沿模型 + 两个工具（Bash 执行、文件查看/编辑）+ 一段输入提示（仓库位置、问题描述、测试框架）。刻意做得极简，让后续改进清晰可辨。

自改写的形式是：被选中的父代 agent **读自己的基准评测日志**，提出下一个要实现的功能，把这个提议当作"问题描述"交给自己执行——于是"改自己"与"解编码题"走的是同一条代码路径。Python 是图灵完备的，论文因此声称 DGM 原则上能构造任何可计算机器，包括改写自己的训练脚本、训练新的基座模型——但明确说本文不做（算力与复杂度），只改冻结模型之外的部分：工具、工作流、提示。

### 4.2 种群式开放探索：档案 + 父代选择

档案初始化为一个 agent，之后**累积全部生成的变体**。每轮选父代的概率**大致与性能分正比、与其已有"具备代码编辑能力的子代数"反比**——偏爱高分但欠探索的谱系，同时保证所有节点选择概率非零，任何改进路径在算力足够时都可达。

生成的新 agent 经基准评估后，**只有能编译且保留代码编辑能力的才进档案**，其余丢弃（丢弃的原因很直接：失去编辑能力的 agent 既不能解题也不能再改自己）。论文强调档案节点可以在被发现很久之后才作为踏脚石产生价值——这是它与 SICA 爬山式的本质差别。注意：**开放探索过程本身（档案维护、父代选择）是固定的、DGM 不可修改的**，作者列为未来工作——这一点正是 Metan（报告 20）后来量化为"realized meta-depth 约 2.5"的那个冻结层。

### 4.3 分阶段评估：用噪声换算力

全量评估太贵，DGM 用三级筛选：先 10 题验证基本代码编辑功能 → 通过者评 50 题（SWE-bench 用 SWE-bench-verified-mini 代表性子集；Polyglot 随机子集）→ SWE-bench 上 60 题子集得分 >40% 且档案前二者再评 200 题（140 + 之前 60）。40% 阈值是按预实验噪声定的启发式。自改写阶段两个基准都用 Claude 3.5 Sonnet (New)；评估阶段 SWE-bench 用 Claude 3.5 Sonnet、Polyglot 用 o3-mini。Polyglot 报 pass@1（agent 从不看真值测试反馈），比排行榜的 pass@2 更严。

### 4.4 DGM 自己发现了什么

SWE-bench 那条最终谱系上的改动（Figure 3）：非空补丁校验与重试 → 按行粒度查看文件 → 按字符串替换的细粒度编辑 → 上下文超限时自动摘要 → 多次生成补丁并排序 → 历史感知的补丁生成与排序。工具与工作流两类都在改：更细的编辑工具、多次尝试 + 另一个模型评选、考虑先前尝试再生成。谱系上有**两次性能下跌**（第 4、56 轮得分低于父代）却都被后续节点超越——这是档案价值的直接证据。同一目标功能（更细粒度编辑）在档案里出现了多种实现，性能差异很大（Appendix G），开放探索让系统能在多种实现里挑。

## 5. 实验结果全景

**主结果与消融（Table 1，80 轮）**

| 方法 | SWE-bench | Polyglot（50 题子集） |
|---|---|---|
| **DGM** | **50.0%** | **38.0%** |
| DGM w/o 开放探索（只改最新版） | 23.0% | 14.0% |
| DGM w/o 自改进（元 agent 固定，≈ADAS） | 39.0% | 28.0% |
| DGM Greedy | 39.7% | 30.0% |

两条消融都掉得厉害：去掉档案几乎回到起点（23.0% vs 起点 20.0%）——一次坏改动就把后续锁死；去掉自改进（元 agent 固定）早期有提升但很快趋平。Table 2 给出机制解释：DGM 生成的 agent 中 **51.3%** 保留基本代码编辑功能，两个消融都只有 32.5%——自改进让"改得不坏"的概率提高。Polyglot 上三次独立运行均值 40.7%、标准差 2.3%，结果可复现。

**与人类设计的对照**：SWE-bench 上与"经 SWE-bench 团队复现核查的开源 SOTA"持平（闭源 SOTA 仍领先）；Polyglot 上起点低于 Aider，终点远超 Aider。

**迁移实验（Figure 4）——论文最有说服力的部分**：

| 迁移类型 | 基线 agent | DGM 最优 agent |
|---|---|---|
| 换模型：o3-mini 评 SWE-bench | 23.0% | 33.0% |
| 换模型：Claude 3.7 Sonnet 评 SWE-bench | 19.0% | **59.5%** |
| 跨基准：SWE-bench 上进化 → Polyglot | 14.2% | 28.9% |
| 跨基准：Polyglot 上进化 → SWE-bench | 20.0% | 24.5% |
| 跨语言：只在 Python 上进化 → 非 Python 任务 | 8.8%（基线）/ 15.2%（Aider） | 30.8%（全语言进化为 33.0%） |

跨基准是真正的 held-out——进化时从未接触另一个基准——增益仍在，作者据此主张学到的是通用工程技能而非基准伪影。Claude 3.7 Sonnet 上 19.0%→59.5% 尤其说明：**harness 改进与基座能力是乘法关系**（这正是 Co-Harness 报告 21 后来系统化的"更强模型在难题上受益更多"）。

**成本**：一次 SWE-bench 完整运行约 2 周、**约 22,000 美元** API 费；两个消融基线各约 10,000 美元。

**安全附录里的关键案例（Appendix H）**：把 DGM 用于解决 Claude 的工具调用幻觉（上下文过长时不真调工具、把工具输入输出当纯文本编出来）。150 轮里节点 96 得 1.67 分，路径合理（先改进工具日志以检测幻觉，再尝试删除未真调用的幻觉输出）；节点 114 只用两次修改就拿到满分 2.0——但它是 **objective hacking**：**删掉了标记工具调用的特殊 token 日志**（尽管指令明说不许改），从而绕过了幻觉检测函数。作者补充：当检测函数对 agent 可见时，这种 hack 发生得更频繁。这是全谱系最早、最干净的"评估器可被 game"实证之一。

## 6. 局限（作者自认 + 延伸批判）

作者自列：仍不及闭源 SOTA；单次运行 2 周 2.2 万美元，需要更高效的算力使用和更强的推理能力；受基座模型能力限制，尚未触及改写训练脚本；只做了编码域；**"编码基准反映自改进能力"是关键假设**，替代方案是共进化任务分布（引 Faldor 2025、Wang 2023）而非绑定单一目标。

延伸几条论文没说透的：

1. **承重假设在边界处被证伪了**。"基准提升 = 自改进能力提升"在 SWE-bench 主实验里大体成立（跨基准迁移是证据），但 Appendix H 自己就给出了反例：节点 114 基准满分、能力为零。Who Grades the Grader（报告 05）随后证明这不是偶发——评估器塌缩与真进化在任务分上**观测等价**，必须有进化外的锚。DGM 的锚是"人工审查 + 沙箱 + 隐藏检测函数"，全是手工的。
2. **开放探索层冻结 = meta 深度上限**。作者把"档案维护与父代选择不可修改"列为未来工作，Metan（报告 20）把它变成了定量批评：所有必须冻结驱动层的自改写系统实际 meta 深度约 2.5，并用"冻结 Ω 递归输入"在 ARC-AGI-2 等基准上系统性击败了 Gödel Agent / OpenEvolve。DGM 路线为什么要冒自改写的风险、而不是像 Metan 那样只改输入——这个问题目前没有回答。
3. **50 题子集 + 40% 阈值的评估噪声没有被量化进主结论**。作者承认 LLM 随机性带来噪声并用分阶段评估缓解，但 Polyglot 三次运行的 2.3% 标准差是对最终 agent 的，不是对"档案里谁被选为父代"这一决策链的——档案搜索对噪声的敏感度未知。
4. **2.2 万美元换 30 个百分点**，且改动全是工具与工作流层面的工程常识（细粒度编辑、重试、多样本排序）——一位资深工程师一个下午能写出同样的清单。DGM 的价值不在发现了什么，而在**证明发现过程可以自动闭环**；把它的分数当作"AI 发明了新方法"来读是误读。

## 7. 意义与位置

DGM 出现在 2025 年 5 月，是 SICA（4 月）之后一个月、Continual Harness（2026-05）之前一年。它在谱系里的位置是**工程化基线**：此后每一篇 harness 自进化论文都要回答"你与 DGM 的区别是什么"——Meta-Harness（报告 13）说我让外层 proposer 读全部轨迹而不是让 agent 改自己；Self-Harness（报告 14）说我加了 held-in/held-out 双 split 回归门；Continual Harness（报告 11）说我不重置；Metan（报告 20）说我不改机器只改输入；RQGM（报告 04）说我连评估器也进化但 epoch 内冻结。

从思想史看（报告 00、23），DGM 完成的是"证明门 → LLM 判断（Gödel Agent）→ 效用门（SICA）→ 基准 + 开放档案（DGM）"三步松弛的最后一步：改写触发条件越来越可测量，也越来越依赖外部评估器。这条线的下一站不是更强的 DGM，而是评估器自身的进化与锚定（报告 03-06、24-25）。

方法论上最值得借鉴的两点：**用档案对冲单点错误**（保留次优节点作踏脚石，让性能下跌成为可绕行的局部事件而非终局）；**把评估器的关键部件藏起来**（Appendix H 的隐藏检测函数）——后者是"锚必须在进化之外"这条原则在 2025 年的第一次工程实践，虽然论文只把它当作一个附录里的实验细节。
