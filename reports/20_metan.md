# Metan（Metaⁿ）深度解读：冻结改进者、递归其输入——不改机器也能拿到深度

> **Metaⁿ: Recursive Self-Improvement through Emergent Depth**
> arXiv 2608.24735 v1（2026-08-25）· 明尼苏达大学 + 首尔国立大学（Zae Myung Kim、Young-Jun Lee、Seungyeon Jwa、Dongyeop Kang）
> 代码：github.com/minnesotanlp/meta-n
> 归档：`papers/en/2608.24735_Metan.pdf` · 中译 `papers/zh/2608.24735_Metan_zh.pdf`

## 1. 一句话定位

现有自改进 agent 改的是**答案**，不是**产生答案的过程**——加了 meta 层的系统把那一层钉死（FunSearch / AlphaEvolve / ADAS，深度 1），能改自身的系统为了不自毁必须留一部分编辑机器不动（Gödel Agent / DGM / HyperAgents，实现深度约 2.5）。Metan 反其道：**冻结元操作 Ω，递归其输入**——Ω 反复读取下层求解栈的执行轨迹 + 产生这些轨迹的代码，写出下一层的策略预处理与可调用 helper 库；Ω 永不变所以不会失稳，输入严格增长所以每层站得比上一层高。深度由收敛决定（实测停在 3–6），进化档案在层链上搜索。八个基准族全部领先：CO-Bench **0.870 vs OpenEvolve 0.702**、AlphaEvolve Math **0.917 vs 0.726**、ARC-AGI-2 **0.331**（OpenEvolve 0.003、Gödel Agent 0.054）。消融把递归的贡献单独隔离：去递归 **−0.131**，且 **72% 的增益来自层间传递的上下文字符串**，可调用代码只占 15%——"条件化"比"代码复用"重要。它是对 DGM 路线的直接批评与替代方案，把 Yudkowsky（报告 00）"每一级提升必须开出新的改进机会"的持续条件第一次做成可测量的 **meta 深度**指标。

## 2. 要解决的问题

论文从一个"深度-稳定性两难"出发：

- **要深度就要改改进者**：如果 meta 层固定，系统只能在同一层面改答案——深度 1；
- **改改进者就要冒失稳风险**：Gödel Agent 用 monkey patching 改自己，DGM 改自己的 agent 代码——但两者都必须保留一部分不可改（Gödel Agent 的 action API、DGM 的档案维护与父代选择），否则系统可能改坏自己的改进能力。论文量化：这些系统实际达到的 meta 深度约 **2.5**。

Yudkowsky（GISAI 2001）的持续条件说：单纯让固定优化器跑得更快不能维持递归改进，每一级提升必须让系统看到或实现**新的改进机会**。Metan 的问题是：**能不能在不改改进者的前提下，让每一级看到新机会？**

答案是让 Ω 的**输入**递归增长——第 d 层的 Ω 看到的是第 1..d−1 层全部的轨迹与代码，信息集严格大于上一层，所以能发现上一层看不到的模式。

## 3. 为什么此前做不通：三条线各差一块

| 已有路线 | 有什么 | 缺什么 |
|---|---|---|
| FunSearch / AlphaEvolve / OpenEvolve | 固定 meta 过程进化程序 | meta 机制不变，深度 1；**逐任务搜索，无跨任务迁移** |
| ADAS / AFlow | meta-agent 设计 agent | 同上，meta 层钉死 |
| Gödel Agent（报告 23） | monkey patch 改自身 | 驱动层必须冻结；深度约 2.5；无档案 |
| DGM / HyperAgents（报告 07） | 改自身源码 + 档案 | 档案维护与父代选择冻结；深度约 2.5 |
| ACE / GEPA（上下文进化） | 进化 prompt 文本 | 单层；无递归堆叠；无 helper 库 |
| Metan（本文） | 冻结 Ω，递归输入 | 见局限 |

关键缺口：**没有人把"深度"当作一个可测量、可消融的变量**——之前的讨论都是定性的（"自指"vs"非自指"），Metan 用 realized meta-depth 与逐层消融把它变成数字。

## 4. 方法机制

### 4.1 三种 meta 改进范式（§2.1，Figure 2）

1. **手工单层 meta**：固定外部 meta 过程重写 agent，meta 机制自身从不改变——深度 1。
2. **自指单层 meta**：agent 改自己的源码，但驱动层必须冻结——深度约 2.5。
3. **递归 n 层 meta（本文）**：meta 过程嵌套堆叠，每一层既是代码的**生产者**（指导 + 库函数）又是下一次 Ω 调用的**对象**。

### 4.2 Ω 的契约（§2.2）

"给定你下方系统的完整执行上下文，写出改进它的代码。"每层输出两件东西：
- **pre_process 块**：策略性预处理——prompt 前缀级的指导（"不要用 scipy""先做 X 再做 Y"）；
- **helper 库 L(d)**：可调用 Python 函数（如深度 2 发出 `fuzzy_match_label()`，深度 3 添加 `reconcile_labels()`）。

Ω 还输出 rationale 块——从深度 3 起，轨迹摘要的格式转向"上一层做了什么、效果如何、该保留/精炼/回滚什么"。

**具体例子**（CO-Bench assignment_problem）：单次 LLM 调用写的脚本 import scipy，沙箱没有 scipy，0 分；扁平自精炼环会反复重试同类导入；深度 2 的 Ω 同时看 36 个任务的轨迹，发现多个任务因相似依赖错误失败，发出"不要用 scipy；这是 validate_output() 工具"——深度 2 求解器重写匈牙利算法得 1.0；深度 3 再看新轨迹 + 深度 2 的代码，决定保留、精炼还是覆盖。

### 4.3 深度由收敛决定

不预设层数，Ω 找不到改进时停止。实测运行停在 **3–6**，原因是 Ω 找不到更多改进，而非基座模型推理能力耗尽或上下文被累积的层代码填满。

### 4.4 进化档案（§2.4）

多候选档案在层链上搜索，报两个估计量——**archive-best**（按任务选最优链）与 **best single chain**（提交一条链）；二者之差是"按任务选择"相对"押注单链"的收益，实测 0.06–0.07。**consolidation mode**：每个候选改进一个焦点任务，档案单调收集跨任务胜利。

## 5. 实验结果全景

### 5.1 主结果（Table 1/2，Gemma 4 31B-IT 与 GPT-5.2 双骨干，seeds 42/43/44）

| 系统 | CO-Bench | SR（符号回归） | AE Math | AlgoTune（×） | ARC-AGI-2 |
|---|---|---|---|---|---|
| **Metan archive-best** | **0.870±0.011** | **0.725±0.014** | **0.917±0.016** | **5.03±0.20** | **0.331±0.010** |
| Metan best chain | 0.806±0.017 | 0.734±0.020 | 0.820±0.024 | n/r | 0.123（1 seed） |
| OpenEvolve | 0.702±0.025 | 0.721±0.007 | 0.726±0.046 | 3.70±0.13 | 0.003±0.001 |
| Gödel Agent | – | – | – | – | 0.054 |

八个基准族全部领先。CO-Bench 上 GPT-5.2 骨干对 OpenEvolve **+0.168**（各 seed 区间不重叠）；符号回归四域全胜。

### 5.2 ARC-AGI-2 是范畴性差距

设计上拒绝技能记忆的基准——OpenEvolve 0.003、Gödel Agent 0.054，Metan 单链仅 0.123，但**完整 meta 栈 + 档案跨任务组合原语达到 0.331**——held-out 上唯一非零的系统。某任务 0.000→0.908。Ω 从轨迹中抽象出 transform 原语，档案跨任务组合它们。

### 5.3 消融（Table 3，CO-Bench）

| 条件 | 分数 | Δ |
|---|---|---|
| Metan 完整（Gemma） | 0.845 | – |
| − 代码库 L(d) 注入 | 0.825 | −0.020 |
| − 层间上下文字符串 | 0.751 | **−0.094** |
| − 递归（只保留深度 1 堆叠） | 0.714 | **−0.131** |
| Metan 完整（GPT-5.2） | 0.886 | – |
| − 递归 | 0.806 | −0.080 |
| Metan 完整（GPT-5.2, AE Math） | 0.917 | – |
| − 递归 | 0.759 | −0.158 |

**条件化是主导通道**：去掉层间上下文（一个字符串）解释了递归增益的 **~72%**；可调用代码库 **~15%**；递归机器本身（beam、retry、inspiration）**~13%**。递归增益随内环天花板下降而增大——正如 §2.3 预测。

**vs 扁平替代**：Gödel Agent 修正配置 + 10× 预算在 GPT-5.2 CO-Bench 上平台在 **0.628**，远低于 Metan 0.870——差距是架构的不是算力的。

### 5.4 角色自发分化（§3.3，596 次 Ω 发射的七类角色标注）

- **rollback 角色**在深度 2 **恰好为零**（两种底座、两位标注者），深度 3 出现（代码 55%、prompt 33%）——纠错是唯一不在深度 2 出现的角色；
- 战术原语在深度 3 达峰（45%），到深度 5 衰减到 17%，被专用库取代；
- meta-strategist / architect / task router / librarian 随深度涌现；
- **prompt 模板从未规定任何角色**。

具体轨迹：`simulated_annealing` 首次在深度 2 的单个候选中出现，传播到 36 个 winner 中的 15 个、跨四个问题族；每条链 d1→d2 都提升（均值 +0.113）；深度 2 的"greedy + local_search"把某任务 0.0→0.759，深度 3 的"simulated_annealing with restarts"再提到深度 4。某些任务只在深度 5–6 首次打开（constrained_guillotine_cutting 深度 5，三个 matsci 任务深度 6）——档案保留浅层 fallback 与深层突破。

## 6. 局限

1. **同一模型坐在所有层**：论文自认这是隔离"深度收益"与"能力收益"的正确对照，但部署场景（强模型当 Ω、弱模型当 base）未测。
2. **"改输入不改机器"是否算 RSI**：按 Bostrom（报告 00）判据——一次改进是否提升了系统发现/验证/实现下一次改进的能力——Metan 的 Ω 自身从未变强，变的只是它看到的东西。这是对"深度-稳定性权衡"的巧妙绕行，但也是对 RSI 定义的一次收缩：它证明了**不改改进者也能拿到深度**，反过来质疑 DGM 路线为什么要冒自改写的风险。
3. **锚仍是外部基准**：八个基准的验证分数是唯一效用信号，档案搜索完全依赖它——评估器塌缩（报告 05）的全部问题一个都没解决，只是被 ARC-AGI-2 这种"设计上抗记忆"的基准部分缓解。
4. **72% 来自字符串条件化**意味着系统的大部分收益本质上是"越来越好的 prompt 前缀"——与 ACE/GEPA 的边界变得模糊，作者也承认下一步该把自由文本换成结构化表示。
5. **深度 3 之后收益递减**：按深度均值峰在深度 3（0.726），深度 6 跌到 0.602——但档案掩盖了这一点（选最优链）。
6. **成本**：CO-Bench 上 17M token 达 0.870——与 OpenEvolve 匹配算力，但绝对成本不低。

## 7. 意义与位置

**对报告 07 DGM 的正面批评**：DGM 的档案维护与父代选择必须冻结才能稳定，Metan 把这一点量化为"realized meta-depth 约 2.5"，并给出不冒自改写风险的替代方案——两条路线的分歧是 2026 年 RSI 架构讨论的主线之一。DGM 说"改自己才是真 RSI"，Metan 说"改自己是不必要的风险"。

**对报告 00 Yudkowsky 持续条件的实证化**：GISAI 说每一级提升必须开出新的改进机会，Metan 的"深度由收敛决定、停在 3–6"正是"新机会枯竭"的量化观测；"输入严格增长所以每层站得更高"是对该条件的工程化满足。

**对报告 23（Gödel Agent → SICA）**：Gödel Agent 在 Metan 的实验里作为基线出现，修正配置 + 10× 预算仍平台在 0.628——自指路线的实际深度上限被直接测量。

**与报告 10 insight 4 的闭环**：自改写深度存在结构性上限、绕行方案已出现——Metan 就是那个绕行方案的完整版本。

**与报告 09 WikiSkill / 报告 26 技能进化的接口**：Ω 输出的 helper 库本质上是跨任务技能编译（librarian 角色），但 Metan 数据显示代码转移只贡献 15%——对"技能资产化"叙事是一个需要认真对待的反面数据点：至少在这个设置里，**好的条件化比好的技能库值钱得多**。技能进化红海五篇都在优化技能库的结构，Metan 说方向可能错了一半。

**对报告 13 Meta-Harness**：两者都"冻结改进者"——Meta-Harness 冻结外部 proposer，Metan 冻结 Ω；区别是 Meta-Harness 的 proposer 只跑一层（改 harness），Metan 的 Ω 递归堆叠。Meta-Harness 若加上递归（让 proposer 看自己之前改 harness 的轨迹并改"改 harness 的方式"），就是 Metan。
