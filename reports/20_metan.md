## 一句话核心主张

现有自改进 agent 改的是**答案**，不是**产生答案的过程**——加了 meta 层的系统把那一层钉死（FunSearch/AlphaEvolve/ADAS），能改自身的系统为了不自毁必须留一部分编辑机器不动（Gödel Agent/DGM/HyperAgents），两条路实际达到的 meta 深度都卡在约 2.5。Metan 反其道：**冻结元操作 Ω，递归其输入**——Ω 反复读取下层求解栈的执行轨迹 + 产生这些轨迹的代码，写出下一层的策略预处理与可调用 helper 库；Ω 永不变所以不会失稳，输入严格增长所以每层站得比上一层高。深度由收敛决定而非预设，进化档案在层链上搜索。

## 方法拆解

**三种 meta 改进范式（§2.1，Figure 2）**。(1) 手工单层 meta：固定的外部 meta 过程重写 agent，但 meta 机制自身从不改变，实现深度 1；(2) 自指单层 meta：agent 改自己的源码，但驱动层（Gödel Agent 的 action API、DGM 的档案维护与父代选择）必须冻结，实现深度约 2.5；(3) 递归 n 层 meta（本文）：meta 过程嵌套堆叠，每一层既是代码的**生产者**（指导 + 库函数）又是下一次 Ω 调用的**对象**。

**Ω 的契约只有一句话**："给定你下方系统的完整执行上下文，写出改进它的代码。" 具体到每一层的输出是两件东西：一段策略性预处理（prompt 前缀级的指导）+ 一个可调用 helper 库。论文的具体例子：CO-Bench 的 assignment_problem 上，单次 LLM 调用写的脚本 import scipy，沙箱没有 scipy，得 0 分；扁平自精炼环会反复重试同类导入方案；深度 2 的 Ω 同时看 36 个任务的轨迹，发现多个任务因相似依赖错误失败，于是发出"不要用 scipy；这是 validate_output() 工具"——深度 2 求解器重写匈牙利算法得 1.0；深度 3 再看新轨迹 + 深度 2 的代码，决定保留、精炼还是覆盖。

**深度由收敛决定**：不预设层数，Ω 找不到改进时停止；实测运行停在深度 3-6 之间，原因是 Ω 找不到更多改进，而非基座模型推理能力耗尽或上下文被累积的层代码填满。

**进化档案（§2.4）**：多候选档案在层链上搜索，报两个估计量——archive-best（按任务选最优链）与 best single chain（提交一条链）；二者之差就是"按任务选择"相对"押注单链"的收益，实测 0.06-0.07。

## 关键数字

- **八个基准族全部领先**（Gemma 4 31B-IT 与 GPT-5.2 双骨干，seeds 42/43/44）：CO-Bench 上 GPT-5.2 骨干对 OpenEvolve 领先 **+0.168**（0.870 vs 0.702，各 seed 区间不重叠）；AlphaEvolve Math 0.917 vs 0.726；符号回归四域全胜
- **ARC-AGI-2 是范畴性差距**：设计上拒绝技能记忆的基准，OpenEvolve 0.003、Gödel Agent 0.054，Metan 单链仅 0.123，但完整 meta 栈 + 档案跨任务组合原语达到 **0.331**——held-out 上唯一非零的系统
- **消融把递归的贡献单独隔离**：去掉递归（只保留深度 1 的 meta 层堆叠）CO-Bench archive-best 从 0.845 跌到 0.714，**+0.131 全部来自递归**；效果在第二骨干与第二基准上复现
- **增益的来源出人意料**：层间传递的上下文字符串贡献约 **72%** 的提升，可调用代码转移只占约 15%——"条件化"比"代码复用"重要
- **角色自发分化**：596 次 Ω 发射的七类角色标注显示，纠错角色（rollback 意图）在深度 3 出现（代码 55%、prompt 33%），meta-strategist / architect / task router / librarian 等角色随深度涌现，且 prompt 模板从未规定任何角色

## 局限与批评

1. **同一模型坐在所有层**：论文自己承认这是隔离"深度收益"与"能力收益"的正确对照，但部署场景（强模型当 Ω、弱模型当 base）未测——深度红利是否在"只升级改进者"时仍成立是自然的下一个实验。
2. **"改输入不改机器"是否算 RSI**：按 Bostrom（报告 00）的判据——一次改进是否提升了系统发现/验证/实现下一次改进的能力——Metan 的 Ω 自身从未变强，变的只是它看到的东西。这是对"深度-稳定性权衡"的巧妙绕行，但也可以读成对 RSI 定义的一次收缩：它证明了**不改改进者也能拿到深度**，反过来质疑了 DGM 路线为什么要冒自改写的风险。
3. **锚仍是外部基准**：八个基准的验证分数是唯一效用信号，档案搜索完全依赖它——评估器塌缩（报告 05）的全部问题在这里一个都没解决，只是被 ARC-AGI-2 这种"设计上抗记忆"的基准部分缓解。
4. **72% 来自字符串条件化**意味着系统的大部分收益本质上是"越来越好的 prompt 前缀"——与 ACE/GEPA 这类上下文进化方法的边界变得模糊，作者也承认下一步该把自由文本换成结构化表示。

## 与本调研的连线

1. **对报告 07 DGM 的正面批评**：DGM 的档案维护与父代选择必须冻结才能稳定，Metan 把这一点量化为"realized meta-depth 约 2.5"，并给出不冒自改写风险的替代方案——两条路线的分歧是 2026 年 RSI 架构讨论的主线之一。
2. **对报告 00 Yudkowsky 持续条件的实证化**：GISAI 说每一级提升必须开出新的改进机会，Metan 的"深度由收敛决定、停在 3-6"正是"新机会枯竭"的量化观测；"输入严格增长所以每层站得更高"是对该条件的工程化满足。
3. **与报告 10 insight 4 的闭环**：自改写深度存在结构性上限、绕行方案已出现——Metan 就是那个绕行方案的完整版本，把 insight 4 从判断变成了有消融支撑的结论。
4. **与报告 09 WikiSkill / 报告 12 综述的接口**：Ω 输出的 helper 库本质上是跨任务技能编译（librarian 角色），但 Metan 数据显示代码转移只贡献 15%——对"技能资产化"叙事是一个需要认真对待的反面数据点：至少在这个设置里，**好的条件化比好的技能库值钱得多**。
