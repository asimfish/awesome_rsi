## 1. 一句话定位

后训练的奖励信号来自哪里，决定了策略能学到什么上限——人类标注不能监督超越人类的能力，专有 API 造成依赖，可验证奖励只覆盖有真值的域。EvoLM 提出一种**不需要任何外部监督**的后训练方法：让同一个语言模型交替训练两种能力——(1) **rubric 生成器**，为每个问题产出实例级评估标准，优化目标是"让一个小型冻结 judge 更容易分辨好坏回答"（判别效用）；(2) **策略**，用 rubric 条件下的 judge 分数作奖励做 GRPO。全部偏好对由策略自己的输出构造（当前 checkpoint vs 更早 checkpoint 的**时间对比**），零人工标注。

关键数字：Qwen3-8B 训出的 rubric 生成器在 RewardBench-2 上比 GPT-4.1 提示式 rubric 高 **25.7%**；共训的策略在 OLMo3-Adapt 十二基准上平均 **69.3%**，比 GPT-4.1 rubric 训出的高 3.9、比 SOTA 8B 奖励模型 Skywork-RM 训出的高 **16%**。

而全文最有份量的发现是一个悖论：**Skywork-RM 在静态偏好基准上一骑绝尘（RewardBench-2 86.4%、JudgeBench 80.8%），训出来的策略却最差（59.7%）**——静态评估标准，无论编码在权重里还是固定 rubric 里，都无法适应学习中的策略制造的奖励地形。本仓库称之为 reward overoptimization 悖论，它是评估侧四篇（报告 03-06）共同的起点。

## 2. 要解决的问题：奖励来源各有天花板，而模型自己的评估知识没被用上

论文开篇的问题诊断：

1. **四种现行奖励来源各有天花板**：人类偏好标注不能监督超出人类的能力；标量奖励模型易被 reward hacking；可验证奖励只覆盖有真值答案的域；专有 LLM-as-judge 造成依赖。
2. **模型自己已经有评估知识**。预训练已经把大量评估性知识编进模型，RL 只是把它显露和锐化而非注入；把这些知识**结构化成可靠打分的形式**，才是自改进的核心挑战。
3. **rubric 是好的结构化形式，但没人训过 rubric 生成器**。在不可验证域，评估可以分解为"rubric 生成（测什么）"和"judging（按标准打分）"——rubric 把评估知识外化为结构化标准，让一个小 judge 在给定具体标准时也能可靠打分，且可检视、可换 judge。已有的 rubric-RL 工作要么靠任务验证器/标注偏好数据，要么靠专有教师生成 rubric；**没有一个方法形式化定义"什么让 rubric 有用"并端到端训练生成器去优化它**。

EvoLM 的答案是一个可测可训的标准：**rubric 有用 ⇔ 它帮助 judge 分辨好坏**。给一个偏好对，直接测 judge 在该 rubric 条件下是否给偏好回答更高分——rubric 质量因此可以直接被测量和训练。

## 3. 为什么此前做不通：设计空间对比

| 方法 | 训练 rubric 生成器 | 无专有 API | 无外部标签 | 不限于可验证域 | 与策略共进化 |
|---|---|---|---|---|---|
| RAR（GPT-4.1 生成 rubric） | ✗ | ✗ | ✓ | ✓ | ✗ |
| RRD（GPT-4.1 迭代精炼 rubric） | ✗ | ✗ | ✓ | ✓ | ✗ |
| RLCER（共训但需任务验证器过滤） | ✓ | ✓ | ✗ | ✗ | ✓ |
| Rubric-ARM（共训生成器与 judge，需参考对） | ✓ | ✓ | ✗ | ✓ | ✗ |
| **EvoLM** | ✓ | ✓ | ✓ | ✓ | ✓ |

前四者各卡在一格：靠专有教师的不能自举，靠验证器的出不了可验证域，靠参考对的需要训练时标签。EvoLM 是唯一五格全满的——代价是必须自己造偏好对（§4.4）。

## 4. 方法机制

### 4.1 把奖励分解为 rubric 生成器 + 冻结 judge

标准做法训一个标量奖励模型 R(q, a)，标准隐含在权重里不可检视。EvoLM 把它拆成两步、中间是自然语言接口：rubric 生成器 ρ_φ 产出 r = ρ_φ(q)，judge J 按标准打分 s = J(q, r, a) ∈ [0, 1]。**judge 全程冻结**——刻意把 rubric 生成器隔离为训练信号唯一的改进来源。默认 judge 是 Qwen3-1.7B：自进化框架预言即使小 judge 在给定判别性 rubric 时也能提供有效奖励，用 1.7B 直接测这个预言。

### 4.2 rubric 作为潜变量：变分推断推出训练目标

好 rubric 的定义是"能判别"：judge 应用它时偏好回答得分更高。把 rubric 视为**解释观察到的偏好的潜变量** r ~ ρ_ref(r|q)，观察到偏好的似然为 p(a⁺ ≻ a⁻ | q, r) = σ(J(q, r, a⁺) − J(q, r, a⁻))——这推广了 Bradley-Terry 模型：偏好由潜 rubric 而非潜标量奖励生成。后验 p(r | a⁺, a⁻, q) 不可解，做摊销变分推断最大化 ELBO：

L = E_{r~ρ_φ(r|q)}[log p(a⁺ ≻ a⁻ | q, r)] − KL(ρ_φ(r|q) ‖ ρ_ref(r|q))

rubric 是离散文本，用策略梯度优化：rubric 生成器作为 agent，收到"正确重建偏好顺序的对数似然"作奖励。实践中把 log-sigmoid 换成**边际奖励 + 格式奖励**：R = α·(J(q,r,a⁺) − J(q,r,a⁻)) + (1−α)·R_format，α = 0.7；边际提供与分差成比例的连续信号，格式奖励（0/1）验证 rubric 符合 judge 可解析的 JSON schema。消融（Table 7）显示格式奖励是 RewardBench-2 从 37.2 跳到 46.0 的关键。

### 4.3 交替训练：K 步策略、K 步 rubric

两者都用 GRPO（组相对优势、无学习价值函数）。策略损失的优势由 judge 分数 J(q, ρ_φ(q), a) 在同问题的回答组内归一化；rubric 生成器的优势在同问题采样的 rubric 组内归一化。**策略更新 K 步时 rubric 生成器冻结，然后 rubric 生成器用策略输出构造的偏好对更新 K 步**（默认 K = 50）。这种交替创造了**涌现课程**：策略进化，rubric 生成器必须学更具体的标准才能在当前输出分布下区分质量；rubric 更判别，策略得到更锐的奖励信号进一步提升。**参数共享**：Qwen3-8B 同时当策略和 rubric 生成器，用不同 prompt 切换角色；两模型配置作为消融（RB2 更高 48.4 但策略持平 69.3）。

### 4.4 三种自造偏好对

rubric 目标需要 (a⁺, a⁻)，全部从策略自身输出构造，默认三种均匀混用：

1. **时间对比（Temporal contrast）**：存下带训练步的 rollout；当前步 t 的回答为 a⁺，更早步 t′ < t 的为 a⁻——策略在训练中变好，所以晚的当偏好。步间距 t − t′ 控制难度：大间距是容易对，小间距需要更细的 rubric；默认 [20, 100]，随训练推进最早的回答被更强的替换，形成自然课程。
2. **推断问题（IQ）**：给 a⁺，让策略自己推断它像在回答什么问题 q̂，再对 q̂ 生成 a⁻——训练 rubric 检查"是否回答了原问题"。
3. **rubric 条件（RC）**：从当前生成器采样 r，用 (q, r) 条件生成 a⁺、只用 q 生成 a⁻——如果 rubric 条件的回答持续更好，说明 rubric 含可操作标准；生成器因此被激励产出能实际改进回答的标准。

## 5. 实验结果全景

**设置**：Tulu 3 偏好混合去重约 27.1 万 prompt（通用对话、IFEval 式指令遵循、数学、代码、科学文献、人设指令）。GRPO 学习率 1e-6、KL 系数 0.001、每题 8 个采样。所有方法统一训 500 步策略更新（RRD、RLCER 每步开销显著更高，Appendix A.7 有成本分解）。评估两轴：下游策略质量（OLMo3-Adapt 十二基准：GSM8K、MATH、HumanEval+、MBPP+、BBH、MMLU、IFEval、PopQA、GPQA、ZebraLogic、AGI-Eval、AlpacaEval v3）与 rubric 质量（RewardBench-2、JudgeBench 判别精度）。

**主表（Table 2）核心列**

| 方法 | RB2 平均（rubric 质量） | JudgeBench 平均 | 策略平均（12 基准） | HumanEval+ |
|---|---|---|---|---|
| GPT-4.1 提示式 rubric | 36.6 | 41.3 | 66.7 | 58.7 |
| Qwen3-8B 提示式 rubric | 26.2 | — | 67.5 | 73.7 |
| **Skywork-RM-V2（标量 RM）** | **86.4** | **80.8** | **59.7** | 47.9 |
| RAR / RRD（冻结 GPT-4.1 rubric） | N/A | N/A | 67.5 / 67.6 | 77.4 / 75.2 |
| RLCER | 45.0 | 49.2 | 66.7 | 80.5 |
| Rubric-ARM | 56.1 | 51.5 | 67.5 | 78.4 |
| Sequential（IQ）/（RC） | 47.2 / 46.0 | 48.6 / 42.2 | 68.0 / 68.3 | 76.5 / 80.2 |
| **EvoLM（共进化）** | 46.0 | 44.4 | **69.3** | **86.2** |

三条读法：(1) EvoLM 策略最强，最大增益在代码（HumanEval+ 86.2 vs 次优 80.5）——细粒度标准在这里给出特别锐的信号；(2) **共进化胜过顺序训练**（69.3 vs 68.3）尽管顺序训练的静态 rubric 精度更高（RB2 47.2 vs 46.0）——下游质量取决于 rubric 是否**适应进化中的策略分布**；(3) **标量 RM 的悖论**：RB2 86.4、JudgeBench 80.8 却训出 59.7 的最弱策略，落后 EvoLM 9.6 分，AlpacaEval 只有 28.3——作者归为 reward overoptimization（Gao 2023、Ivison 2024）：静态标准无法适应学习中策略创造的奖励地形，共进化 rubric 靠持续重构标准避开这个失败模式。

**机制：rubric 从抽象标签进化为可验证检查（§3.2.1）**。定性分析四个域，早期 rubric 用短标签或通用检查，训后 rubric 把具体可验证的期望塞进每条标准：数学里把 80% 权重集中在一条嵌入期望答案的标准上（"由周长 48 导出的正确最大面积 144"），把证明验证变成答案核对；受限写作里把格式与关键词要求合并为可数检查。100 个评估 prompt 上的统计：**纯标签标准从 21.9% 降到 0.3%，嵌入具体期望值的标准从 6.9% 升到 19.3%，约束型标准从 7.7% 升到 20.3%**。共同效果是把评估从小 judge 做不好的整体语义判断，变成对具体标准的模式匹配——这是边际目标的直接后果：任何拉大 judge 分差的标准都被奖励，具体可验证的自然胜过抽象的。标准长度单调增长（59 → 112 字符），条数稳定在 3-4。

**泛化（§3.3）**：OOD 深度研究任务上与专家 rubric 的成对一致——HealthBench **58.4% vs GPT-4.1 52.5%**，ResearchQA **59.3% vs 51.0%**；冻结的 rubric 生成器迁移到未见策略（Qwen3-4B、Llama-3.1-8B）仍优于 GPT-4.1 rubric；跨 judge、跨架构（OLMo-3-7B）均成立；多 judge 训练的生成器对训练集合之外的 judge 也更可解释。

两条反直觉：**更大的 judge 不带来更好的策略**（4B judge RB2 61.6 但策略 66.5，低于 1.7B 的 69.3）；**三种偏好信号合用 RB2 最高（49.3）但策略最低（67.8）**——rubric 静态精度与策略质量再次脱钩，与主表的标量 RM 悖论同一方向。

## 6. 局限（作者自认 + 延伸批判）

作者自认：只在通用后训练数据上验证，医学/法律等专域混合未知；rubric 富化机制在有可验证中间步骤的任务上最清晰，对纯主观标准的效果刻画不足；**冻结 judge 是刻意的设计选择**（隔离 rubric 生成器为唯一改进源），但它限制了生成器能学会产出的标准复杂度。

延伸几条：

1. **悖论的解释只有一半**。论文把"静态 RM 判分越准策略越差"归为 reward overoptimization，这解释了为什么静态标准会被利用，但没解释为什么**共进化的 rubric 不会被利用**——它同样是策略正在优化的目标。Who Grades the Grader（报告 05）给出的答案是：共进化评估器不塌缩靠的是锚（这里是冻结 judge + 时间对比的"晚的更好"假设），而任务分本身证明不了这一点。EvoLM 的时间对比假设——晚 checkpoint 必然优于早 checkpoint——是一个未被检验的锚。
2. **RB2 与策略质量的脱钩在消融里反复出现**，却被当作"共进化的优势"而非"评估器基准可能测错东西"来读。若 RB2/JudgeBench 不预测下游策略质量，那么用它们证明"rubric 生成器超过 GPT-4.1 25.7%"这条头条数字的意义也要打折。
3. **rubric 进化的方向是"可验证化"**——把数学题 80% 权重压到答案核对上。这在有唯一答案的任务上等价于引入了隐式验证器，属于合理的能力；但在真正开放的任务上，同一机制会奖励**把主观质量降维成可数特征**——这是 Goodhart 的经典入口，论文没有在开放任务上检查 rubric 是否变得狭窄。
4. **十二基准里 GSM8K/MATH 基本饱和**（95 左右），差异全来自 HumanEval+、BBH、AlpacaEval 三项；69.3 vs 66.7 的平均差异主要由代码撑起。

## 7. 意义与位置

EvoLM 在 2026-05 出现，是评估侧四篇（报告 03-06）里**最早也最系统地把评估器放进训练环**的工作：RQGM（报告 04）在 epoch 内冻结评估器、边界换尺；Who Grades the Grader（报告 05）证明必须外置人工锚；ECHO（报告 06）让 critic 与 policy 双路 GRPO 同步。四篇合起来回答了 DGM（报告 07）留下的问题——"基准提升是否等于能力提升"——答案是：只有当评估器随策略一起动、且有一个不动的锚时，才等于。

它的**标量 RM 悖论**是本仓库反复引用的实证：报告 10 insight 1（评估器是双重瓶颈）与 insight 3（评估器与策略的相对速度决定系统命运）都以它为主要证据。SCORE（报告 22 综述提及）随后把"评估器与求解器共享参数联合训练"推到权重层，EvalCEGAR（报告 24）把评估器进化做成可读的算子池——两条后续路线分别对应 EvoLM 的两个设计选择：参数共享，与"可检视的自然语言接口"。

方法论上最值得借鉴的三点：**把"什么让评估器有用"形式化为可测目标**（判别效用 = judge 在该 rubric 下的分差），而不是让评估器自由进化；**用时间对比免费造偏好对**（"后来的自己胜过以前的自己"，代价是这一假设成了系统唯一的、未被检验的锚）；**冻结 judge、只进化 rubric**——用一个不动的部件换取可归因性，这与全谱系"锚在进化之外"的纪律一致，即便论文没有这样命名它。
