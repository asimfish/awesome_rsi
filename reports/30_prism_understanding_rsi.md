## 1. 一句话定位

这篇长文是 Prism-Shadow/awesome-rsi 清单（报告 29）元数据的叙述版：先给 RSI 一个统一定义 A(t+1) = U(A(t), τ(t), f(t))——agent 用第 t 轮的轨迹 τ 和反馈 f，经更新机制 U 得到下一轮的自己——再沿五组维度展开：**进化对象**（参数 / 上下文 / 记忆 / 技能 / harness 代码）、**进化结构**（链 / 树 / 图）、**更新者**（自身 / 教师 / 联合）、**更新时机**（离线 / 在线 / 混合）、**其他五维**（验收标准、反馈来源、反馈类型、更新频率、经验范围）。每个类别配一篇代表论文，用两到四段说明它属于该类的原因和主要数字。文章的目标是让读者拿到一篇新论文时能迅速定位它与已有工作的关系，它做到了这一点；它没有做的是判断哪种选择更好，也没有讨论评估器本身会被优化压力带偏这一问题。与本仓库的关系：它的"进化对象"对应本仓库的"改哪层"，它的"验收标准"对应本仓库的"锚在哪"，它多出"进化结构"和"更新者"两个本仓库没有单列的维度。

## 2. 文章要解决的问题

作者的出发点与本仓库相同：RSI 领域没有统一范式，不同工作改的东西、改的方式差别很大，"自进化""Self-Evolving""Self-Improving"几个词混用，读者难以比较。作者的回答不是给出一条主线，而是给出一套坐标：先把 agent 拆成 Model + Harness，把 harness 拆成上下文、记忆、技能、工具、代码，再问每篇论文改了哪一块、新版本怎样继承旧版本、谁来改、何时改、凭什么留下。

这套坐标的价值在于可操作：每个维度的取值是有限的、互斥或可多选的，所以可以直接变成清单上的标签（报告 29 的 methodTaxonomy.js 就是这篇文章的数据化）。

## 4. 内容拆解

### 4.1 定义与更新公式

A(t+1) = U(A(t), τ(t), f(t))。A 包含模型与 harness；更新可以落在模型参数，也可以落在 harness 的上下文、记忆、技能、工具或代码；U 不一定由 agent 自己执行，也可以由教师、meta-agent 或外部训练程序完成。这个定义比本仓库报告 00 引用的 Bostrom 判据宽：Bostrom 要求"一次改进提升了做下一次改进的能力"，本文只要求"更新后的状态参与后续任务并提升表现"。按本文定义，任何带记忆的 agent 都算 RSI；按 Bostrom 定义，多数记忆方法不算。文章没有讨论这个差别。

### 4.2 进化对象：五类各一篇代表

| 类别 | 代表论文 | 文章给出的要点 |
|---|---|---|
| 参数进化 | SEAL（Self-Adapting Language Models，2025-06） | 模型面对新输入时不只生成答案，还生成 self-edit（重组信息、生成训练样本、指定超参、调用工具做增强），系统按 self-edit 做 SFT；外层用 RL 训练"什么样的 self-edit 有效"，奖励是更新后模型的下游表现。代价是候选 self-edit 的微调和评测开销大 |
| 上下文进化 | Prime Agent（2026-08） | 持久 IPython REPL 保存代码、变量、文件和计算结果；Continual Harness 记录历史、记忆、技能、prompt 和子 agent 配置；任务中断后从现场恢复。不更新参数，模型再次运行时由 harness 取出所需内容组成上下文 |
| 记忆进化 | ReasoningBank（2025-09） | 把成功和失败轨迹整理成简短可复用的经验，新任务先检索再执行，结束后判断是否完成并写回；MaTTS 让 agent 对同一任务多次尝试以提炼更高质量的记忆。WebArena 成功率 +3.7 到 +6.2，SWE-Bench Verified 解决率 +3.4 到 +4.0 |
| 技能进化 | TRACE（2026-08） | 车载助手场景（CAR-bench），Skill Bank 中每个技能负责一类情况；每轮收集用过同一技能的成功和失败轨迹，比较行为后修改该技能。GPT-5.5 上"同一任务连续三次全部成功"的比例从 59.9% 提到 94.5% |
| harness 代码进化 | SkillSmith（2026-05） | 同时修改技能和工具：发现能力缺口后生成配套修改（调整技能、编辑/组合/拆分/停用工具）；记录技能之间的合作与干扰关系决定优先调用或淘汰；保存失败模式避免重复试错。五个规模的 Qwen3.5 上，任务越复杂优势越明显 |

文章对上下文与记忆的区分是：记忆存在外部等待检索，取出放入模型输入后才成为上下文。对技能与记忆的区分是：记忆记录某次发生了什么，技能总结以后遇到同类问题怎么做。

### 4.3 进化结构：链、树、图

| 结构 | 定义 | 代表 | 数字 |
|---|---|---|---|
| 链 | 始终只有一个当前版本，A0 → A1 → A2 …；实现简单，前一轮的错误直接被继承 | SkillFlow（基准，2026-04） | 20 个任务族、166 个可执行任务；Claude Opus 4.6 成功率 62.65% → 71.08%，部分配置持平或下降；表现好的配置反复修订少量通用技能，差的不断新增相似技能 |
| 树 | 保留多个版本，一个版本可生成多个子版本，后续可从任意历史版本继续；暂时表现差的版本也保留 | DGM（2025-05） | SWE-bench 20.0% → 50.0%，Polyglot 14.2% → 30.7%；一次完整实验约两周；选父代和管理版本集合的规则预先设定、不随 agent 更新 |
| 图 | 一次修改同时参考多个来源（同一 agent 在不同任务的轨迹、另一分支的执行结果） | Mendel Gödel Machine（2026-08） | 在 DGM 的单轨迹 clonal mutation 之外加 reaction-norm mutation（比较同一 agent 跨任务的轨迹）和 cross-lineage hybridization（比较不同分支在同一任务上的表现）；Polyglot 50.8% → 93.2%，单轨迹树形基线 77.9%；进化出的 harness 换基准或换模型后仍有效 |

这个维度是本仓库没有单列的。本仓库在报告 07 讨论了 DGM 的档案，在报告 20 讨论了 Metan 的档案与单链之差（archive-best 与 best chain 差 0.06–0.07），但没有把"拓扑"作为独立轴。Mendel Gödel Machine 的 93.2% 对 77.9% 是这个维度最直接的证据：修改依据来自多个来源时，同样的评估预算下效果更好。

### 4.4 更新者：自身、教师、联合

文章把执行任务的 agent 称为 Student，分析轨迹并参与修改的另一个 agent 称为 Teacher，并给出三条判定规则：Student 自己总结并修改是自身更新；Student 只执行、Teacher 决定写回什么是教师更新；两者都影响最终写回内容才是联合更新。**只提供分数或验收结果的模块不算 Teacher**——这条规则把评估器排除在更新者之外，与本仓库把评估器单独作为"锚"讨论是一致的。

代表论文：Recuris（教师更新，固定的 Meta-Agent 汇总多任务失败记录并局部修改 Skill Memory；四个长程基准、十种模型、37 个组合中 35 个提升，最长任务最多 +32.2）；Evo-Harness（联合更新，Solver 总结候选经验、Evolver 筛选整理写入；去掉 Solver 的候选生成后效果下降）。

本仓库对应的对照是 Meta-Harness（教师更新，外部 coding agent 改 harness）与 Self-Harness（自身更新）。文章对自身更新的风险判断是"Student 理解错误时，错误也会写入长期产物"，这与本仓库报告 14 讨论的回归门必要性是同一件事，但文章没有给出解决办法。

### 4.5 更新时机：离线、在线、混合

| 模式 | 定义 | 代表 | 数字 |
|---|---|---|---|
| 离线 | 训练任务中更新，测试阶段不再更新；训练题与测试题不能重复也不能分布完全不同 | GDPevo（基准，2026-08） | 用 Rule Hybridization 构造任务：同一批基础规则以不同组合出现在 5 个训练任务，重新组合成 5 个测试任务；12 组共 120 个任务，两天可再生成 12 组。最好配置 50.63% → 67.07%；直接给出全部规则时 91.6%，说明 agent 只学到了部分规则 |
| 在线 | 任务排成序列，边执行边更新，无独立训练阶段 | FinEvo-Bench（基准，2026-08） | 120 个金融任务、6 个领域、20 个场景各 6 个任务交错排列，顺序随机打乱三次；**每次实验配一个状态重置的对照组**，两组分数之差即保留经验的提升。四种 Qwen3.7-Max agent 平均 +9.33 到 +19.37；同一场景后三个任务的提升比前三个高 6.10 到 8.70 |
| 混合 | 先离线建立初始经验，上线后继续更新 | Mem²Evolve（2026-04） | Experience Memory 存经验，Asset Memory 存工具和专家 agent；新工具先过自动生成的单元测试。六类任务八个基准，比只积累经验高 11.80%，比只创建工具高 6.46% |

FinEvo-Bench 的状态重置对照组是文章里对评测方法学最有用的一点：它把"提升来自积累的经验"与"提升来自模型本身"分开测量。这正是 Prism-Shadow 基准表里 Gain 指标的实现方式，也是本仓库报告 12 批评 TMLR 综述"现有基准测不到知识积累"时缺少的正面例子。

### 4.6 其他五个维度

验收标准（产物验证 / 单题结果 / 基准得分 / 组合指标 / 无独立验证）、反馈来源（基准 / 训练验证集 / 环境 / 可执行验证器 / LLM 反馈 / 人工）、反馈类型（分数：二值或非二值；非分数：标准答案、LLM 评审、其他）、更新频率（单步 / 事件触发 / 完整轨迹 / 批次）、经验范围（通用 / 专用）。这一节只给定义不给代表论文，对应报告 29 里 methodTaxonomy.js 的后五个维度。

## 5. 与本仓库主线的对照

**验收标准就是锚，但文章不讨论没有锚会怎样。** 文章把"无独立验证：生成后直接写入"列为五种验收标准之一，语气中立。本仓库的证据（报告 05：去掉锚定守卫后评估指标退化，任务分数看不出来；报告 16：去掉 dev 集检查后自动优化低于未优化基线）说明这一格不是一种设计选择，而是一个已知会失败的配置。两边合起来读，文章的分类给出了"锚在哪"的取值空间，本仓库给出了每个取值的后果。

**文章的 RSI 定义比 Bostrom 宽。** 按 A(t+1) = U(A(t), τ, f)，ReasoningBank 这类记忆方法是 RSI；按本仓库报告 00 采用的判据（一次改进是否提升了做下一次改进的能力），它们是经验积累而不是递归改进。这不是谁对谁错的问题，而是两个仓库选了不同的边界：Prism-Shadow 收录范围更宽，本仓库更窄。读者引用"RSI"一词时需要知道说的是哪个定义。

**文章没有覆盖的部分**：评估器共进化（EvoLM、RQGM、WGtG、ECHO）、模型与 harness 共同训练（Continual Harness 的共学习环、Co-Harness）、安全治理、能力地板、思想史。这些正是本仓库的主要内容。反过来，文章的进化结构维度和 Mendel Gödel Machine、Recuris、SEAL、ReasoningBank 几篇代表论文是本仓库应该补的。

**两个可以直接对照的例子**：
- Prime Agent：文章把它归为上下文进化的代表，强调持久 REPL 和现场恢复；本仓库报告 18 强调的是它的 refinement 把 RCON 作弊固化成技能这一安全事故。同一篇论文，一边看能力，一边看风险。
- DGM：文章把它归为树形结构的代表并指出"选父代和管理版本集合的规则不随 agent 更新"；本仓库报告 07、20 把同一事实解释为自改写系统必须冻结一部分，并由 Metan 量化为 meta 深度约 2.5。

## 6. 局限

1. **只分类不评价。** 文章说明每种选择的优缺点（例如参数进化"难以定位和撤销"、链式进化"错误直接被继承"），但不比较哪种选择在什么条件下更好，也不引用消融证据。
2. **代表论文 13 篇，每类一篇。** 读者从一篇代表论文推断整个类别的特征，样本太少；例如"图式进化"只有 Mendel Gödel Machine 一个例子。
3. **不讨论评估器可靠性。** 全文默认反馈 f 是可信的。反馈来源里列了 LLM 反馈，但没有提 LLM 评审可能被优化压力带偏（报告 03）或与被评模型合谋（报告 05）。
4. **数字未标出处。** 文章引用的数字（如 TRACE 59.9% → 94.5%、MGM 50.8% → 93.2%）没有标注论文表号，读者需要回原文核对。
5. **定义过宽带来的后果未讨论**（见 §5）。
6. **中英双语但以中文为主写成**，英文版为翻译；个别术语（如"验收标准"对应 Acceptance criterion）在两版间需要对照。

## 7. 意义与位置

**对本仓库分类图（§3）的补充**：本仓库的七个一级维度里没有"进化结构"和"更新者"。前者有直接的实验证据支持其重要性（MGM 对 DGM 的 +15.3 个百分点），后者与本仓库反复讨论的 Meta-Harness / Self-Harness 对照直接相关。下一版分类图可以把这两个维度加进去。

**对报告 10 insight 6（经验必须先整理成知识再变成技能）的补充**：文章对上下文、记忆、技能三者给出了清楚的操作定义，本仓库此前在知识侧混用这三个词。采用文章的定义：记忆是外部存储、检索后才进入上下文；技能是跨任务的做法；上下文是本次推理直接看到的材料。

**对报告 12 的呼应**：本仓库批评 TMLR 综述"现有基准从构造上测不到知识积累"，文章用 FinEvo-Bench 的状态重置对照组给出了怎样测的实例；GDPevo 的 Rule Hybridization 给出了怎样构造"不重复但相关"的训练与测试任务。

**对报告 29 的关系**：报告 29 分析清单的数据结构，本报告分析支撑该结构的论述。清单里每篇论文的标签，就是按本文的定义打的。

**应补入本仓库的论文**（按优先级）：Mendel Gödel Machine（框架侧，DGM 直接后续，有强数字）、ReasoningBank（知识侧记忆线的起点）、SEAL（权重侧，模型自己决定怎么训练自己）、FinEvo-Bench 与 GDPevo（基准，对照组设计）、Recuris（教师更新的长程记忆实现）。
