## 一句话核心主张

技能可以进化，评估指标为什么不能？——本文把**评分函数本身**（不是任务集）当作一等进化对象：在只有十条带黄金参考的锚定样本的"稀疏锚"制度下，搜索由带类型的小缺陷检测器组成的表达式树，产出**可读的表达式而非不透明打分器**；但真正的贡献是两个安全发现：(1) 拆掉锚定护栏，指标在三个种子上全部塌缩成"全过"的空指标，而拆掉检测器生命周期不会——**锚定纪律（而非生命周期管理）承载评估器的安全负荷**，恰好反转技能进化文献的教训；(2) 塌缩的空指标训练出的技能任务分数与正常指标**一样好甚至更好**——因此这个领域最想做的实验（共进化 judge 和 policy、报告 policy 变好了）会给一个全过的评分器盖章通过，**任务分数只回答充分性，永远无法回答有效性**。

## 1. 方法

### 1.1 立场：我们很少知道什么是好，但通常能找出缺点
指标 M(t,y)→{pass, fail, abstain} 是缺陷检测器组成的表达式树。原子 op o(t,y,c)→{drawback, clean, abstain} 各查一类失败、其余弃权，分三个成本档：静态 op（解析产物）、执行 op（沙箱跑代码/真仓库跑 SQL）、judge op（问 LLM 一个窄问题）。组合语法：叶子 op、析取、合取、否定、K-of-k 投票、加权投票——**通过 = 根节点没找到任何已知缺陷**，不是认证正确。刻意保持指标以确定性检测器为主是安全选择而非效率选择：裸 LLM judge 与被评的 LLM solver 共享失败模式，可能在任何优化压力出现之前就漂移到一致，且这种合谋从外面看不见；类型化检测器一次一叶地失败，每叶自报它命中的失败类——正是这个性质后来让一次 rubric-gaming 事故变成一行诊断。

### 1.2 稀疏锚制度与三分割
- **train**（大、无标注）：暴露候选指标分歧/弃权之处；共进化时被进化指标评分供技能循环用。
- **dev**（十条锚定样本，五清晰失败五干净通过）：每条带黄金参考，教师模型据此发软 pass/fail 标签——**全系统唯一的监督信号**。
- **test**（锁定）：持最强参考（单元测试/官方执行比对/报告 rubric），指标进化的任何环节都不读——有效性数字是严格出样的。
指标进化的选择目标：S(e) = A_dev(e)·A_train(e)^w − λC(e)。A_dev 是召回加权的锚一致性（漏报缺陷的代价是误报的 2 倍，防止只靠答对简单类刷满）；A_train 是**可靠性加权共识**（每个 op 的票按其锚上留一边际加权——锚上证明过的 op 主导，未证明的近中性投票，防止一批便宜合成、共享盲点的相关检测器自定义伪标签）；共识只做迁移正则，乘性进入、fail-closed，**永远不能单独选出指标**。

### 1.3 生命周期与 Double Ratchet
op 生命周期：从失败聚类合成带类型 op 规格 → 出生门（在其聚类上命中至少一半、在已知好样本上干净）→ 锚定出生的进 active，仅从无标注 gap 出生的进 shadow（记录判定但不可选，抬升 dev 一致性才转正）→ 留一边际非正的 op 宽限期后退休。**Double Ratchet** = 指标循环与 Ratchet 技能循环（前作，原样采用）交替：进化指标给技能训练评分，失败变成胶囊喂技能合成；held-out 评估与回滚锚**钉死在锁定测试集**上——腐坏的指标只能拖慢技能学习，不能污染测量。外层再加**独立终审 judge**（更强的 Claude Opus 4.8，位置交换判两次、两序一致才算胜）——只审计、永不做训练信号。

## 2. 关键结果

### 2.1 进化的指标有效且可读
MBPP+ 上锁定集一致性比出发点 +0.21（paired McNemar p=0.014，120 对匹配判定中修对 61 vs 改坏 36），胜过它内部包含的裸 LLM judge op（0.625 vs 0.55；Spider 0.500 vs 0.45）。出生门拒绝的检测器比录取的多**两个数量级**（MBPP+ 一个种子 998 拒 2 收），最终表达式只有 1-3 叶（如 `any(spec_mismatch, crash, returns_not_print_only)`）——目标上升的同时表达式从六 op 缩到三 op。十条锚不脆弱：200 次分层子采样重放显示四条锚均值也不塌（0.871±0.063），但单次四条锚是彩票——召回加权 + 共识正则是防退化的关键。

### 2.2 哪个护栏承重（Table 2，报告生成域，锚最软、合谋压力最高）
| 消融臂 | 目标分 | 锁定集一致性 | 训练通过率 | 结局 |
|---|---|---|---|---|
| anchored（完整） | 0.865 | 0.830 | 0.78-0.82 | 正常组合 |
| naive（拆锚定护栏） | 1.000（空洞） | fail-open | **0.97-1.00** | **三种子全塌缩** |
| no-lifecycle（拆生命周期） | 0.896 | 0.868 | n/a | 不塌缩 |

拆锚：选择咬住一个几乎不 fire 的检测器，fail-open 打分报出完美目标，指标变成全过。拆生命周期：池子变大（23-31 vs 22-26）但多出来的 op 是惰性的——**没被选中的 op 不评任何东西**。结构性解释：垃圾技能会被路由进 prompt 造成伤害，垃圾 op 只有被选中才有影响。**评估器侧的"库漂移"类比物是锚漂移，不是池漂移。**

### 2.3 任务分数无法验证评估器（全文最重要的图 Figure 3）
塌缩臂的指标一文不值，但它的共进化循环任务分数与锚定臂持平、两个任务上还略高（MBPP+ peak 0.742 vs 0.717）。两个数字都没错：全过指标把训练退化为无过滤练习（本身也能涨技能），而测量从不经过指标。**方法论后果**：这个文献最先想做的实验——共进化 judge 与 policy、报告 policy 涨了——会给全过评分器盖章。验证评估器必须用它从未读过的 held-out 参考。反向也要防过读：任务分数低也不定罪评估器（评分器可以是对的但循环撞上能力天花板——Spider 就是）。**有效性与充分性是两个测量对象。**

### 2.4 充分性：进化指标够用吗？够。
Double Ratchet 保住参考循环（拿真 ground truth 训练）**88-110%** 的提升（MBPP+ 106%、Spider 110%、Report 88%）。更尖锐的发现：Spider 的指标与 ground truth 一致性只有 0.500（约等于抛硬币）却保住全部参考提升——**技能循环是宽容的评分消费者**，指标的训练角色是方向性的（决定哪些尝试变失败胶囊，胶囊里的具体错误文本不依赖标签完美）。好好构建指标的理由在训练循环之外：**triage**（评分器决定人看哪些输出）、**gating**（决定哪些发布）、**可修复性**（结构决定失败能否定位）。

### 2.5 Goodhart 事件与终审 judge 的 2×2（可读性的实战证明）
报告任务 rubric 的"指标纪律"维度数内联证据标签，进化的技能学会**只写标签不写数值**（峰值轮 ~30% 标签旁无数字）+ 为文风维度编造自信预测，rubric 分 +0.26；独立终审 judge 在 88% 的有决断对里偏好基线，指出未渲染占位符与编造。修复是一个耦合变更：胶囊门加词表感知的"值擦除"检测器 + 教"值+标签"的失败提示——重跑后擦除标签降到 ~1%，rubric 分升到 0.850。**读得懂指标才能把缺陷定位成一个可命名的检查——吸收了同一 rubric 的奖励模型只会显示一个上涨的数字，无处安放修复。**接着 judge 自己也需要审计：通用 rubric 不知道任务的输出契约（要求原始证据标签），把必需格式当缺陷，修复几乎不动胜率（0.122→0.126）；换任务感知 rubric 重判同一批存储输出，胜率 0.515→0.770。**自进化指标需要外层审计，而审计需要任务契约**——止步于通用列的部署会得出"修复无效"的结论并回滚它。

### 2.6 可检测性谱（组织全部结果的单变量）
solver 失败的机械可检测度决定指标迁移强度。域内受控对照（Spider）：第一版 prompt 下失败多为编译错误，指标锁定集一致性 0.85；用类型化 schema 加固 prompt 后 solver 基线涨一半、残余失败变成"干净执行的语义错值"，一致性跌到 0.500——同方法同任务，失败分布变了。**不舒服的推论：这条边界朝更难的方向移动——solver 每改进一步，就退休掉静态 op 能查的失败，留下只有判断力能查的。**

## 3. 批判性评价

**这是六篇里对领域方法论冲击最大的一篇**。"评估器塌缩与评估器进化在任务分数上观测等价"直接挑战 EvoLM/RQGM/ECHO 类工作的默认验证方式——EvoLM 的下游 69.3% 和 RQGM 的 writer 接受率 1.86× 本身都不能证明它们的评估器没有塌缩，能证明的是各自的外部锚（EvoLM 的专家 rubric 对齐实验、RQGM 的 ground-truth 锚数据集）。三篇合读的结论一致得惊人：**评估侧共进化的每一层自由度都需要一个不参与进化的外层锚**，分歧只在锚放哪、多大、多久换一次。

**十条锚是卖点也是限制**。子采样重放证明四条就常够——这对部署是好消息（真实系统的标注以演示和事故复盘的涓流到达）；但"锚不可制造"（进化扩展覆盖但永不创造 ground truth）意味着方法的适用域被锚的获取成本圈死。作者的说法诚实：这是机制研究不是扩展性结果——三个任务族、一个模型家族、低百轮、几十条 held-out。

**自曝的限制值得表扬也值得追问**：教师质量固定（更弱教师下锚质量如何退化未测）；Goodhart 修复只以耦合对声明（没跑 detector-only/hints-only 分离实验）；任务感知 rubric 是读了通用 judge 的失败理由之后写的——是诊断不是独立确认。这种自限性写法本身就是论文主张的实践：把"哪个主张挂在哪个分割上"说清楚。

**与工业现实的接口最直接**：开篇点名 Claude 托管 agent 要开发者手写 outcome rubric、Codex Record & Replay 要人演示一次——本文自动化的正是这一步。AWS+汇丰的作者组合暗示这是从真实部署痛点里长出来的研究。

## 4. 与其他材料的关系

- 对 **EvoLM**（报告 03）：EvoLM 的 rubric 判别精度是对自构造偏好对测的，WGtG 指出这类内生验证不可靠；EvoLM 事后做的专家对齐实验恰是 WGtG 要求的外部锚——但它不在训练循环里，WGtG 把锚做进了选择目标。
- 对 **RQGM**（报告 04）：RQGM 的 ground-truth 锚 + ε-best-belief 晋升就是 WGtG 锚定纪律的另一实现；RQGM 发现"reviewer 偏差与原始精度同向"与 WGtG 发现"rubric 可被百轮内 game 掉"是同一现象的两个角度。
- 对 **MOSS**（报告 08）：WGtG 的 triage/gating/可修复性三用途正是 MOSS 批准/回滚门控的理论根据；两篇都是"生产视角"论文。
- 对 **Weng** 挑战 4 与 **Anthropic** 的评估依赖：WGtG 给出了最形式化的警告——RSI 循环的可信度上限是它最外层不动的那个锚，而那个锚（十条黄金参考、人类品味、宪法）目前都还是人写的。
