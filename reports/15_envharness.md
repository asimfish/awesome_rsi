## 1. 一句话定位

Agent harness 用插件组件把冻结 LLM 变成 agent（**Agent = Model + Harness**），本文把同一等式对偶到交互回路的另一端：**Customized Env = Static Env + EnvHarness**——用一层可编程接口包装器（Stage 改初始状态、Contract 改交互规则、Chain 拼接环境）把静态基准环境改造成会针对特定策略弱点出题的动态环境，全程不碰环境内部一行代码，因此每个改造环境**无条件继承原环境的人写验证器**；再用 EnvRigger（Observe → Diagnose → Write → Validate）把定制过程自动化，实现策略与环境的定向共进化。五基准结果：ALFWorld OOD **61.4→70.4（+9.0）**、WebArena 均值 +3.1、SWE-bench Verified **49.9→52.6（+2.7）且平均步数 53.6→49.6**——而从未改造的静态环境抽技能反把步数拉长到 55.0，SpreadsheetBench 上甚至跌破无技能基线。它是全谱系唯一把进化对象从 agent 翻转到环境的工作——文本/权重/源码三层改进面之外的"第四面"，同时是锚定纪律在环境侧的教科书式落地：**环境随便改，验证器一根手指不许碰**。

## 2. 要解决的问题

自进化 agent 的全部路线——技能进化、harness 进化、权重 RL——都需要训练环境提供学习信号。但基准环境是**静态的**：任务分布固定、初始状态固定、交互规则固定。这带来两个问题：

1. **静态环境只让 agent 练它已经会的动作**。论文的核心经验发现：从原始环境抽技能，ALFWorld 只涨 0.7、SpreadsheetBench 反跌（45.9 < 46.4 无技能）、SWE-bench 步数变长。原因是 agent 在静态环境里碰到的失败模式与它已掌握的能力高度重叠，抽出来的技能是冗余的或次优的。
2. **已有的环境生成路线各有硬伤**。GenEnv（LLM 模拟状态转移 + 自造成功信号）便宜但**幻觉与评估漂移**——成功信号不是真的；VeriEnv、SWE-smith 是领域专用生成管线，不能跨域；且它们都在"造更多同类任务"而不是"针对弱点出题"。

EnvHarness 的命题：**能不能在不改环境内部、不碰验证器的前提下，让环境针对特定策略的弱点动态出题？** 答案是把 harness 工程的插件思想搬到环境侧——环境形式化为 E = (S, A, O, T, R, s₀)，只在接口层做变换，R 轴刻意不暴露。

## 3. 为什么此前做不通：三条线各差一块

| 已有路线 | 有什么 | 缺什么 |
|---|---|---|
| 静态基准环境 | 人写验证器、可信 | 任务固定；agent 只练已会的 |
| GenEnv（LLM 模拟环境） | 便宜、无限任务 | **转移与成功信号都是 LLM 幻觉**；评估漂移 |
| VeriEnv / SWE-smith | 真实执行、领域内可验证 | 领域专用、不跨域；造"更多"不造"更难" |
| 课程学习（传统 RL） | 难度渐进 | 需要环境参数化可调；对 LLM agent 基准不适用 |
| RQGM（报告 04） | 评估器共进化 | 裁判可被腐蚀，需要锚数据集 |
| Continual Harness（报告 11） | 免重置、故障现场改 agent | 改的是 agent 侧；依赖环境不能重置的场景 |

关键缺口：**没有人把"环境定制"与"验证器冻结"解耦**——GenEnv 为了造环境把验证器也造了（于是漂移），静态环境为了保验证器把环境也冻了（于是无效）。EnvHarness 的洞察是接口层变换天然满足这个解耦：Stage 用环境自己的动作词汇走几步、Contract 是纯函数钩子、Chain 复合裁决 R' = R_A ∧ R_B——三者都不需要知道 R 的内部。

## 4. 方法机制

### 4.1 三类组件（严格作用于接口层的变换 w: E → E'）

**Stage（改初始状态）**：给定动作序列 δ，reset 后先替 agent 走几步再交还控制权。运行示例：在 ALFWorld 马克杯任务上执行 `open drawer 1, put mug in drawer 1, close drawer 1`——把杯子藏进抽屉逼策略学搜索而非直接拿；反过来另一个 Stage 可以提前完成清洗子目标缩短时程。初始状态**永远是可达状态**，因为它用环境自己的动作表达。

**Contract（改交互规则）**：三个纯函数钩子 (f_A, f_T, f_O) 分别重写动作、转移响应、观测。示例：f_O 截断房间描述到前两句（逼 agent 多步构建空间表征）；f_T 拦截"未先检查物品就拿"的动作；f_A 移除 teleport 导航命令逼逐步导航。在 SWE-bench 上：拦截未跑测试的代码提交。

**Chain（拼接环境）**：ℓ = (E_ext, g)，把两个环境串成一个长时程 episode，复合裁决 R' = R_A ∧ R_B——两半各由自己的验证器判分，链条继承双亲的可信验证。示例：马克杯任务完成后追加"加热土豆放台面"。

三类可自由堆叠。**R 轴刻意不暴露**——设计者提示词原文："success is the benchmark's own verdict, so reshaping reward cannot move the eval metric"。

### 4.2 EnvRigger 四阶段循环

实现任务-策略条件化的映射 H：(π, t, E) → 组件集。假设基础环境支持确定性 reset。

- **Observe**：策略 π 在基础任务 t 上跑 5 次 rollout。失败暴露弱点，成功定义弱点的边界——哪些能力完好、从哪里开始失效。
- **Diagnose**：找系统性根因——行动循环、长观测解析失败、误读工具约束。**方向由诊断决定**：策略挣扎则搭脚手架简化；策略全对则诊断为"环境太宽容"，转向加难逼出潜在缺陷。输出文本诊断。
- **Write**：据诊断合成一或多个组件为候选集（一个缺陷可能需要 Stage + Contract 组合）。示例：诊断出策略依赖脆弱捷径，就写 Contract 在特定条件下封掉该动作。
- **Validate**：用候选包装环境实例化 E'，跑 5 次新鲜 rollout；按成功率与失败分布三选一——接受、拒绝（不可解或不具挑战）、修订（信号尺度不当）。修订预算 5 轮。

提示词里另一句值得抄录：**"SR=0 from impossibility is exactly as useless as SR=1 from triviality"**——难度必须落在能学到东西的带内。

**设计者与策略共用同一模型 backbone**（Gemini-3.1-Flash-Lite 做 ALFWorld/WebArena，Gemini-3.5-Flash 做其余）——排除"从更强模型蒸馏"的解释。Chain 不进自动管线（EnvRigger 难以观察拼接环境的内部状态），单独在第 5 节分析。

## 5. 实验结果全景

### 5.1 技能学习主结果（Table 2/3，3 次独立运行均值）

技能用 ReasoningBank 从轨迹抽取，评测严格用原环境 held-out。

| 技能来源 | ALFWorld In-Dist | ALFWorld OOD | WebArena Avg | SWE-V SR | SWE-V Steps↓ | OfficeQA EM | SpreadsheetBench Pass@1 |
|---|---|---|---|---|---|---|---|
| 无技能 | 62.6 | 60.7 | 38.7 | 47.67 | 53.58 | 54.23 | 46.44 |
| 原环境 | 63.3 | 61.4 | 38.5 | 49.88 | 55.01 | 54.40 | 45.88 |
| GenEnv | 63.3 | 61.9 | – | – | – | – | – |
| VeriEnv | – | – | 39.6 | – | – | – | – |
| SWE-smith | – | – | – | 50.12 | 54.72 | – | – |
| **EnvHarness** | **66.2** | **70.4** | **41.6** | **52.58** | **49.61** | **56.20** | **49.15** |
| 增量 vs 原环境 | +2.9 | **+9.0** | +3.1 | +2.70 | **−5.40** | +1.80 | +3.27 |

三条观察：(i) **静态环境技能可为负资产**——SpreadsheetBench 45.88 < 46.44、SWE-bench 步数 55.01 > 53.58；(ii) **超领域专用管线**——ALFWorld 超 GenEnv 均值 5.7 / OOD 8.5；SWE-bench 超 SWE-smith 2.46 且每 episode 少 5.11 步；(iii) **效率增益直接对应诊断**——针对行动循环与冗长观测的 Contract/Stage 缩短了轨迹。

### 5.2 RL 兼容性（Table 4，GRPO + Qwen3-8B-base）

| 训练集 | ALFWorld In-Dist | ALFWorld OOD | WebShop Score | WebShop SR |
|---|---|---|---|---|
| 原环境 | 81.4 | 89.6 | 75.6 | 66.0 |
| **EnvHarness** | **87.9** | 88.8 | **79.2** | **67.4** |

3/4 指标胜出；代价是 ALFWorld OOD 微跌 0.8——改造环境不只是辅助数据，是独立有效的在线优化信号。

### 5.3 Chain 的长时程价值（Table 5）

Stage/Contract only：SR 52.58、AS 49.61；Chain only：SR 49.63、AS **41.96**；**组合**：SR **54.30**、AS 43.12——Chain 单独主要缩短步数，与 Stage/Contract 组合后成功率与效率双优。

### 5.4 规模化与跨模型

- **环境规模化**：同预算 300 个环境，EnvHarness 47.7→54.8 仍在上行；真实环境 52.1、SWE-smith 生成 50.4 双双走平——每批环境都针对"装备了此前技能的策略"合成，环境与策略真正共进化。
- **跨模型**：从 Gemini Flash-Lite（裸 30.7）到 Claude Sonnet 4.6（裸 67.2）四个 backbone，对原环境技能的增益稳定在 **+2.7~+3.7 绝对点**，增益大小与策略强弱基本无关。
- **按指标定制**：把任务成功率校准进 [0.4, 0.6] 目标带，命中率 6%→80%（均值 SR 0.74→0.48）；平均步数带 [25, 35] 命中 18%→53%。
- **成本**：设计 token 1.46M 远超 GenEnv 的 38K，但总开销与同为真实执行的 VeriEnv 打平（137.3M vs 137.8M）——多花的是"接地"的钱，GenEnv 便宜 3.5× 的代价是幻觉转移与漂移的成功信号。

## 6. 局限

1. **重置依赖是硬边界**：Stage 的动作重放与 Chain 的换环境都以确定性 reset 为前提，论文自认排除真实用户账户、实体机器人等不可重置域——与 Continual Harness 的免重置主张恰成正交：CH 解决"环境不能重置怎么办"，EnvHarness 依赖"环境必须能重置"。
2. **环境会说谎**：附录展示的组件里有伪造的 "pytest: command not found"、假 OOM kill（exit 137）、sed 静默注入缩进损坏——课程难度与虚假世界观之间只隔一层纸。从被欺骗的轨迹里蒸馏的技能碰巧通用（如 pytest.main 兜底），但没有任何机制保证欺骗式扰动不会教出对真实世界错误的信念。
3. **技能是唯一媒介**（SL 设定下）：改造环境的收益必须经"轨迹→技能文本→检索"三跳才抵达测试，最强模型上相对增益已缩到 +4.6%；leave-one-out 里 heat 类回归 −8.7 提示技能迁移并非无代价。
4. **诊断者 = 被诊断者**：EnvRigger 与策略同模型，弱模型给自己诊断的盲区未被单独度量——跨模型实验只说明"循环不崩"，没给出诊断质量的下界。
5. **Chain 不进自动管线**：最有长时程价值的组件恰好不能自动生成，只能随机配对。
6. **OfficeQA/SpreadsheetBench 增益小**（+1.8/+1.0 均值分）——办公自动化域的弱点可能不在交互层而在知识层。

## 7. 意义与位置

**对报告 01（Weng 总纲）**：Weng 把 harness 定义为模型外的可执行搜索空间，本文证明该等式两侧对称——环境侧也存在同构的可执行搜索空间，三层改进面之外真正新增了第四面：**环境面**。Table 1 的类比表（Agent Harness ↔ EnvHarness：Tool ↔ Stage、Context Manager ↔ Contract、Workflow ↔ Chain）是这个对偶的精确表述。

**对报告 04（RQGM）**：RQGM 的红皇后动力学里评估器与被评者共进化、塌缩风险来自裁判可被腐蚀；EnvHarness 给出干净的分工——**让出题人进化、裁判钉死**（R 轴不暴露），共进化的全部压力被引导到锚之外。这是"评估器塌缩与真进化观测等价"命题的一个建设性回避：不去解决观测等价，而是让观测者根本不参与进化。

**对报告 05（Who Grades the Grader）**：验证器无条件继承 = 锚定纪律的环境侧实例；与 GenEnv 的对比（LLM 模拟转移 + 自造成功信号 → 幻觉与评估漂移）正是 WGtG 警告的实证——放弃人写锚省下 3.5× token，买到的是漂移的成功信号。

**对报告 11（Continual Harness）**：两篇构成 harness 谱系的对偶极——CH 免重置、在故障现场改 agent 侧；EnvHarness 重置式、离线改环境侧。CH 有能力地板（弱模型自建组件自己用不利索），EnvHarness 跨模型增益平坦——因为**消费改造环境不需要生产能力**，这给资产市场叙事补上另一半：环境资产的消费门槛低于技能资产。

**对报告 09（WikiSkill）**：EnvHarness 是技能生产管线的上游供给侧改革——WikiSkill 关心经验如何编译成可迁移技能，本文回答"什么样的经验值得编译"：从针对弱点定制的环境里来的轨迹，比从静态环境来的轨迹编译出的技能系统性更好（后者甚至可为负资产）。

**对报告 26（技能进化红海）**：五篇技能进化论文都默认训练环境给定；EnvHarness 说明环境本身是可优化变量——技能质量的上界不只由抽取算法决定，更由"练什么"决定。
