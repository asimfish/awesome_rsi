## 1. 一句话定位

2024–2025 年间，"agent 修改自身源码"从思想实验变成可运行系统，但代价是**把 Schmidhuber 的形式证明门换成经验效用门**。Gödel Agent（2024-10）用 **monkey patching** 让 LLM 在运行时直接读写自身的内存与逻辑，只靠高层目标提示驱动——GPT-3.5 系上 DROP / MGSM / MMLU / GPQA 达 **80.9 / 64.2 / 70.9 / 34.9**，全面超过 Meta Agent Search（79.4 / 53.4 / 69.6 / 34.6）。SICA（2025-04）把这套机制放到 SWE-Bench Verified 上，用**显式效用函数**（U = 0.5·score + 0.25·cost + 0.25·time）选最优版本，随机子集从 **17% 提升到 53%**，并第一次把**异步监督者**做成自改写系统的标配安全部件。两篇填补报告 00（1965–2014 思想史）与报告 07（DGM 2025-05）之间的空档：DGM 从前者继承名字与"改自身代码"的野心，从后者继承编码域、效用驱动与安全约束，再加上自己的开放式档案。这条线上最重要的转折点不在 DGM 而在 SICA：**监督者的引入承认了自改写系统需要一个不参与改写的观察者**——锚定纪律（报告 05）在安全侧的第一个工程雏形。

## 2. 要解决的问题

Schmidhuber 2003 的 Gödel Machine 给了 RSI 一个形式化定义：系统可以修改自身任何部分，**包括修改机制本身**，但只有当它能形式证明"修改后效用更高"时才执行修改。这个定义在理论上完备，在实践上**永远不会触发**——对任何非平凡系统，证明"改后更优"的搜索空间是不可计算的。

2024 年的问题是：**LLM 能不能替代证明？** LLM 可以读代码、理解意图、判断"这样改会不会更好"——如果这个判断足够可靠，就可以用它代替形式证明，让 Gödel Machine 从理论变成系统。

但这立刻引出两个后续问题：
1. LLM 的判断不是证明，会错——**错了怎么办？** 需要外部验证（基准）或监督（overseer）。
2. 什么都能改，包括"判断该不该改"的部分——**怎么防止系统改坏自己的判断力？** 需要留一部分不可改。

Gödel Agent 主要回答第一个问题的"能不能"，SICA 回答"错了怎么办"，DGM 回答"留什么不改"。

## 3. 为什么此前做不通：三条线各差一块

| 已有路线 | 有什么 | 缺什么 |
|---|---|---|
| Gödel Machine 2003 | 形式化完备的自指定义 | 证明门永不触发 |
| Meta Agent Search / ADAS（2024） | meta-agent 搜索 agent 设计 | **meta 层固定**，只搜 agent 不搜搜索者 |
| Self-Refine / Reflexion | LLM 反思改输出 | 改的是答案不是代码；无持久改变 |
| AutoML / NAS | 自动搜索架构 | 搜索空间人定；不自指 |
| 手工 agent（CoT、Debate） | 可靠 | 不进化 |

关键缺口：**Meta Agent Search 停在"搜索 agent"这一层，没有让搜索者自己进搜索空间**。Gödel Agent 声称可以搜索整个 agent 设计空间——包括修改自己的搜索逻辑；实际上（Metan 报告 20 后来量化）action API 必须冻结，realized meta-depth 约 2.5。

## 4. 方法机制

### 4.1 Gödel Agent（2024-10）

**机制**：受 Gödel Machine 启发，agent 通过 monkey patching 直接读取和修改运行时内存中的自身逻辑——决策函数 f、动作函数 o、甚至 agent 算法 (π, I) 本身。不依赖预定义例程或固定优化算法；整个搜索空间只受高层目标的提示约束。

**四个必须包含的动作**：读环境 / 读自身逻辑 / 修改自身逻辑 / continue_improve（无其他动作可选时，触发 f 产生新动作）。

**两个版本**：
- **Gödel-base**（受约束：闭卷、GPT-3.5、无外部资源）：公平对比用；
- **Gödel-free**（无约束：可调用更强模型或外部资源）：90.5 / 90.6 / 87.9 / 55.7——作者用斜体标注，不是公平对比。

### 4.2 SICA（2025-04）

**核心设计三件**：

1. **显式效用函数**：
   U = 0.5·score + 0.25·(1 − cost/$10) + 0.25·(1 − time/300s)
   超时按 τ = 0.5 比例罚——**第一次把"更好"定义成多目标而非单一基准分**。

2. **版本档案**：每次自改写产出新版本，在基准上评估后选最优者作为下一轮的改写者与被改写者（改写者 = 被改写者，真自指）。

3. **异步监督者（asynchronous overseer）**：一个独立 LLM 线程每 30 秒（或关键事件）读取系统状态的完整文本表示（所有事件流、agent 调用、工具输出），判断 agent 是否偏离或卡死并可干预——**工具、子 agent 与监督机制本身也在可自改范围内**（论文自认这是一个开放的安全问题）。

**工具集**：基本编码工具 + 子 agent 委托 + overseer 通知通道。

## 5. 实验结果全景

### 5.1 Gödel Agent（Table 1，GPT-3.5 系，± 为标准差）

| 方法 | DROP | MGSM | MMLU | GPQA |
|---|---|---|---|---|
| Chain-of-Thought | 64.2±0.9 | 28.0±3.1 | 65.4±3.3 | 29.2±3.1 |
| Meta Agent Search | 79.4±0.8 | 53.4±3.5 | 69.6±3.2 | 34.6±3.2 |
| **Gödel-base** | **80.9±0.8** | **64.2±3.4** | **70.9±3.1** | **34.9±3.3** |
| Gödel-free（不公平） | *90.5±1.8* | *90.6±2.0* | *87.9±2.2* | *55.7±3.1* |

MGSM 上 +10.8 是最大增益；GPQA 上 +0.3 在噪声内。发现的策略：推理前先规划、优先计划而非仓促行动。

**后续评估**：Metan（报告 20）实测 Gödel Agent 在 ARC-AGI-2 上 **0.054**，CO-Bench 上 **0.451**（远低于 OpenEvolve 0.814）；修正配置 + 10× 预算平台在 0.628——无档案、单链自改写在难任务上容易陷入平台。

### 5.2 SICA

- **SWE-Bench Verified 随机子集：17% → 53%**（Table 1 逐轮）；
- LiveCodeBench 与合成 agent 基准（文件编辑、符号定位）亦有提升；
- 全程考虑安全约束与资源预算；
- 作者定位其为"数据高效、非梯度、由 LLM 反思与代码更新驱动的学习机制"。

## 6. 局限

**Gödel Agent**：
1. **无档案、单链**——改坏了没有回退；
2. **action API 冻结**——"搜索整个设计空间"的声称不完全成立；
3. **QA/数学基准**——不是 agent 任务，改的是推理策略不是 harness；
4. **Gödel-free 的数字不可用**——但被广泛误引。

**SICA**：
1. **随机子集**而非全量 SWE-Bench Verified；
2. **效用函数权重手设**（0.5/0.25/0.25）——"更好"的定义本身是人的选择；
3. **监督者与被监督者同源**（同一 LLM 家族），属于自评；
4. **监督机制本身可自改**——作者自认是开放安全问题；SICA 没有回答"谁监督监督者"。

**共同局限**：两者都用**基准分**做改写的最终裁判——这正是 DGM 后来遇到的伪造日志、绕过检测的结构根源（评估器是静止靶）。

## 7. 意义与位置

### 桥接表：三步松弛

| 要素 | Gödel Machine 2003 | Gödel Agent 2024 | SICA 2025 | DGM 2025-05（报告 07） |
|---|---|---|---|---|
| 改写触发 | 形式证明"改后更优" | LLM 判断 + 目标提示 | 效用函数 + 基准评估 | 基准评估 + 档案选择 |
| 搜索结构 | 单链 | 单链 | 版本档案（选最优） | 开放式档案（多父代、保留次优） |
| 安全部件 | 无（证明即安全） | 无 | **异步监督者** + 资源约束 | 沙箱 + 人工审查 + 档案回溯 |
| 域 | 通用 | QA/数学 | 编码（SWE-Bench/LCB） | 编码（SWE-bench/Polyglot） |
| 不可改部分 | 无（理论上） | action API | 隐含（基础工具） | 开放探索循环 |

**对报告 00 的接续**：Schmidhuber 的证明门在 Gödel Agent 里被替换为"LLM 觉得更好"，在 SICA 里被替换为"效用函数说更好"，在 DGM 里被替换为"基准说更好"——**三步松弛越来越可测，也越来越依赖外部评估器**，直接导向报告 05 的评估器塌缩问题。

**对报告 07 DGM 的溯源**：DGM 论文的两项核心主张（自改写可行、档案多样性重要）分别在 Gödel Agent 与 SICA 里有原型；DGM 的增量是把两者合并、加大规模、并加上"保留表现差但可能是踏脚石的版本"。

**对报告 20 Metan 的对照**：Metan 把 Gödel Agent 作为 baseline 系统性击败，并归因于"驱动层冻结导致 meta 深度 2.5"——本报告的两篇正是 Metan 批评的靶子。读完可以判断这一批评是否公允：Gödel Agent 的确单链无档案，SICA 有档案但仍是单 meta 层。Metan 的替代方案（冻结 Ω、递归输入）与 Gödel Agent 的哲学（什么都能改）正好相反。

**对报告 08 MOSS 的前史**：SICA 的异步监督者 → DGM 的沙箱人审 → MOSS 的批准/回滚门控，是"自改写系统的安全部件"三年三级跳；SICA 是这条线的起点。

**对报告 05 WGtG**：SICA 的 overseer 是"不参与改写的观察者"——锚定纪律的雏形；但 overseer 与 agent 同源、且 overseer 本身可改，锚不独立。WGtG 后来把这个直觉理论化为"评估器不得参与进化"。

**对报告 28 Coding 综述**：综述把 SICA 与 DGM 并列为"用结果证据验证自改写"的代表，并列为基准过拟合风险最高的一类——本报告的桥接叙事与综述的风险判断一致。
