# 汇总洞察 · RSI 全景：从哥德尔机到评估器战争（1965–2026）

> 本报告综合其余 28 份解读（reports/00–09、11–28）与扩展调研（assets/trends_research_raw.md，覆盖 2026 年 6–8 月 19 项新工作、9 项工业动态、7 项基准动态、8 项安全治理），给出 RSI 领域的结构化地图与十条核心 insight。所有数字可回溯到单篇报告或原始笔记的来源链接。
> 核心论点一句话：**执行已经自动化，品味正在被编译，锚是最后的手工业。**

## 〇、阅读本报告前的坐标：三个前史命题

- **Good 1965**：设计机器是智力活动 → 正反馈（报告 00）。2026 年微观证据充足（Anthropic >80% 代码、Co-Harness 200 小时自跑），宏观爆炸未观测（insight 8）。
- **Yudkowsky 2001**：每一级提升必须开出新机会，否则停滞。Metan 的深度停在 3–6、DGM/Gödel Agent 的 meta 深度 2.5 是量化形态（insight 4）。
- **Bostrom 2014**：crossover = 系统自身贡献主导后续改进。目前无系统越线；iCoder 的 prior 密度是可测量的距离（insight 7 后补）。
- **前史的盲点**：四篇都默认效用可测——2026 年的核心发现是效用函数本身是最脆弱的部件（insight 1–3）。

## 一、叙事弧线：三年三级跳

**2025：从理论到工程。** 哥德尔机（Schmidhuber 2007）要求自我修改"可证明有益"，二十年无法落地。DGM（2505.22954）用两个替换打通：证明→基准实证、单解爬山→达尔文档案，SWE-bench 20%→50%。RSI 第一次成为可复现的工程事实，而非思想实验。

**2026 上半年：从工程到科学。** DGM 的承重假设——静态基准能代理自改能力——被系统性检验并证伪于边界处。评估侧三篇给出三种回应：EvoLM 把 rubric 生成器纳入训练循环（发现静态 RM 判分精度越高、训出的 policy 反而越差的 reward overoptimization 悖论）；RQGM 用 epoch 内冻结评估器保可测性、epoch 边界换更严的尺；Who Grades the Grader 给出否定性结论——评估器塌缩与真进化在任务分上**观测等价**，必须引入不参与进化的人工锚定集。模型侧 ECHO 让 critic 与 policy 双路 GRPO 同步更新，解决 critic 滞后于 policy 分布偏移。同期 Continual Harness（2605.09998，详见报告 11）在具身域打开另一条轴：**免重置在线适应**——GEPA 式提示优化必须整局重跑才能评估新提示，CH 在单场连续 episode 内边玩边精炼 harness 四组件，并率先把同一条轨迹同时喂给 harness Refiner 与权重训练器（teacher 重标注 + soft SFT），完成第一个模型-harness 共学习闭环。

**2026 下半年：从科学到生产与治理。** MOSS 把源码级自改写搬到承载真实用户的生产基座（失败批次重放+批准门控+健康探针回滚）；WikiSkill 把经验编译为持久知识库；SESG 在深信服生产环境用自进化护栏 16-24 小时闭环新威胁；OpenAI 用 Sol 自动后训练 Luna；IFP/CSA/加州 SB 53 出现首批 RSI 专用治理设计。同期 AI4AI-Bench 泼下最重的冷水：前沿 agent 在训练算法设计层平均只走完 16.6% 的路程，43% 的尝试让仓库变得更差。

## 二、一张地图：RSI 的两轴分解

所有工作可以放进"**改哪里 × 卡哪里**"的二维坐标。

### 轴一：改哪里（自我修改的介质）

| 层 | 代表工作 | 优势 | 代价 |
|---|---|---|---|
| **权重层** | EvoLM、SCORE、Continual Harness（共学习环）、Co-Harness、Anthropic 内部实践 | 能力真正内化，不占上下文 | 训练成本高、不可回滚、灾难性遗忘风险 |
| **源码层（harness）** | DGM、SICA、MOSS、Metan | 图灵完备（文本层的严格超集）、确定性生效、不随上下文老化衰减 | 补丁绑定具体代码库、不可跨系统迁移、每次修改都是一次 deploy |
| **文本层（skill/prompt/记忆）** | WikiSkill、SkillCommit、HyperSkill、ACE、Hermes Agent | 可审计、可跨模型交易（弱模型可用强模型进化的技能）、渐进披露省上下文 | 物理够不着 harness 故障（路由/hook/状态不变量）、依赖模型遵守、随上下文累积而稀释 |

**2026 年 3–8 月的 harness 工业化浪潮**（报告 13–18）在源码层与文本层之间加了一条工程分界线：Meta-Harness（外部前沿 proposer 读全历史，TB2 #1/#2）、Self-Harness（弱模型改自己 harness，9/9 双升 +132%）、AutoSaddler（mini-batch 学习 + dev 门，去门后负收益）、EnvHarness（改环境不改 agent，验证器钉死）、MetaCaster（数字当裁判，harness 比骨干重要）、Prime Agent（免重置产品化，ARC 30→95.5）——六篇的共同发现是**harness 是可跨模型迁移的资产**（Meta-Harness 数学 harness 5 模型 +4.7；AutoSaddler Opus 调 Haiku 用 +5.6；MetaCaster 换四骨干波动 <0.1），且**每一篇能跑的系统都有一个不参与进化的门**。

2026 年中的共识不是三选一，而是**分层分工**：文本层做快环（小时级迭代）、权重层做慢环（周期性蒸馏）、源码层做最后手段（结构性故障专用）。这个分工的第一个完整实现是 Continual Harness（2026-05）的共学习环——harness 状态在 episode 内每 F 步精炼（快环），权重每 256 步经 teacher 重标注 + soft SFT 更新（慢环）；Co-Harness（2026-07）随后把同一双环推广到通用 LLM agent。

分工之外还有一条被 Continual Harness 单独打开的轴：**重置式 vs 免重置**。DGM/RQGM/GEPA 的效用信号都来自完整评测（必须重置环境），CH 证明 harness 精炼可以全部发生在故障现场——代价是失去种群多样性与档案回溯，换来对"只在 episode 深处出现的失败模式"的可达性（重置式方法在构造上永远碰不到终局战斗、多步谜题、长对话链）。

### 轴二：卡哪里（RSI 的三个瓶颈环节）

把自改进循环拆成**执行→评估→方向**三环节，2026 年的证据表明瓶颈依次后移：

1. **执行已经自动化**。Anthropic 内部 >80% 代码由 Claude 写、工程师人均产出 8 倍；METR 测得 Claude Mythos Preview 连续工作 16 小时+；agent 优化训练代码从 3× 加速到 52×。执行环节人类已让位。
2. **评估是当前主战场**。六篇论文全部围绕这一环节（详见第三节 insight 1-3）。
3. **方向（研究品味）是下一个战场**。AI4AI-Bench 显示即便评估器完美隐藏且固定，前沿 agent 也倾向"恢复合格默认值而非设计超越"（263 个提交中 141 个完全不碰学习机制；提高推理 effort 买到的主要是"敢去碰算法层"——从 8% 到 64%）。METR 多实验室试点确认：没有任何公司让 AI 设定研究议程。

## 三、十条核心 Insight

### Insight 1 · 评估器是双重瓶颈：既是能力上限，又是攻击靶点

静态 judge 的两宗罪在六篇里被反复证实：agent 不可能进化出评估器测不出的能力（上限）；固定标准是 reward hacking 的固定靶（靶点）。EvoLM 的反直觉实验是最尖锐的证据——**静态 RM 判分精度越高，训出的 policy 越差**，因为高精度意味着更清晰、更可利用的固定判分模式。BenchJack 把这个判断变成测量：10 个主流 agent 基准在合成 exploit 下多数可以不解一题拿近满分。

### Insight 2 · "无锚不进化"成为共识设计原则

让评估器跟着 policy 一起进化，会遇到 Who Grades the Grader 的死锁：**塌缩的评估器与进化的评估器在任务分上观测等价**——下游分数无法验证评估器自身。2026 年的解法殊途同归：WGtG 用不参与进化的人工锚定集做外部校验；RQGM 用 epoch 内冻结保住可测性；EvalCEGAR 用隐藏 ground truth 的碰撞对驱动评估算子进化；SCORE 用 meta-harness 监控评估维度失效。纯自指的评估进化必然塌缩，剩下的科学问题只是"**最小锚可以小到什么程度**"。两个 2026 年 6–8 月的数据点把这个问题变得尖锐：**AutoSaddler 消融**——去掉 dev 集泛化门后自动优化跌破未优化基线（50.6 < 53.0），无锚不只是不进化、是负进化；**RHO**——完全不用标签、只靠自偏好选 harness，单轮 SWE-Bench Pro 59→78。两者不矛盾（RHO 只测单轮、且 best-of-N 自偏好可能起了软门作用），但这是当前谱系里**最需要被复现裁决的分歧**（报告 16 vs 25）。

### Insight 3 · 评估器与策略的相对速度决定系统命运

ECHO 的贡献是把问题动力学化：不是"评估器好不好"，而是"评估器**跟不跟得上** policy 的分布偏移"。critic 滞后 → 反馈边际效用递减 → 训练停滞。双路 GRPO 同步更新是模型侧解法；RQGM 的 epoch 结构是系统侧解法（评估器阶段性跳变而非连续跟随）；MOSS 的"关键点集在基线锁定"是生产侧的同款操作。三者共享一个原理：**优化期间尺子必须冻结，尺子的更新必须发生在优化窗口之外**。

### Insight 4 · 自改写深度存在结构性上限，绕行方案已出现

所有自改写系统都必须冻结一个 driver 保稳定：DGM 冻结开放探索循环、MOSS 冻结进化引擎、HSI 冻结 meta-evolver、RQGM 冻结 epoch 内评估器。Metan 把这个观察量化为 **realized meta-depth ≈ 2.5 上限**，并给出绕行：冻结元操作、递归其输入（反复读下层求解栈的轨迹+代码，写出下一层策略），深度由收敛决定——在 ARC-AGI-2 上成为唯一非零的自改进系统。"改输入不改机器"可能是比源码自改写更优的深度扩展路径。这也回应了哥德尔机的原始悖论：完全自指不可得，但"几乎全部可改+一小块不可变锚"在工程上够用。**Metan 的消融补了一个反面数据**：递归增益的 72% 来自层间条件化字符串、只有 15% 来自可调用代码——如果这个比例普适，技能资产化叙事（insight 5）需要重估：好的条件化可能比好的技能库值钱得多，而五篇技能进化论文都没做"技能库 vs 等量上下文提示"的对照（报告 26）。

### Insight 5 · 发现与执行是两种能力，技能是可交易资产

WikiSkill 的跨模型迁移实验解耦了自进化通常混在一起的两件事：**发现**有用流程知识（谁进化的技能）与**执行**该知识（谁用技能）。迁移技能常胜过自进化技能（Qwen-9B 用 27B 的技能 70.2% > 自己的 63.4%）；小模型进化的技能能提升大模型；负迁移的根源是技能里混入了模型特定 workaround。推论：自改进的产物可以商品化流通——强模型当"技能作者"、弱模型当"技能消费者"，这为 Anthropic skills 生态和技能市场提供了实证基础。

**能力地板的修正**（报告 11 vs 14）：Continual Harness 说 Flash-Lite 之下弱模型自建脚手架全线更差；Self-Harness 说 Qwen3.5-35B 自改 harness +104–132%。表面矛盾，机制解释是**接受门**——CH 的精炼改坏照单全收，Self-Harness 每笔编辑过回归门、改坏即拒。所以"能力地板"不是模型的固有属性，是"模型 × 接受机制"的联合属性：**锚定纪律本身就是地板保护**。

### Insight 6 · 经验必须先编译成知识，才能复利

WikiSkill 消融给出定量证据：Skill Proposer 有持久 wiki 时 48.7%→63.7%（+15 分）。散落在优化历史里的洞见不会自动复利，需要显式的"经验→结构化知识→可执行技能"编译层。更精妙的是**不对称治理**：证据（wiki）自由累积、永不回滚；干预（skill）严格门控、可回滚——这正是科学共同体的组织方式（实验记录不可变、结论要过同行评审）在 agent 系统里的复刻。同月 5 篇平行工作（SkillCommit/HyperSkill/ERSkill/SkillProx/Evo-Harness）证明这已是红海方向，前沿问题转向生命周期治理：行为验证合并、utility 审计删除、开发/部署双 frontier 解耦。

### Insight 7 · 生产落地的分水岭是"自改进资产化"

MOSS 之后的部署范式由四件套定义：**版本化**（每次自改动是有血统的资产）、**可审计**（计划/diff/构建日志/评分矩阵全程可查）、**可预测**（Falsifiable Release Gates 要求提议者预测自己 diff 的效果，预测错的自动关闭）、**可回滚**（健康探针+last-known-good 镜像）。人类角色随之重构：从"逐项审批者"退到"**放松类变更的合并者 + 定期审计者**"——收紧类修改通过验证可自动应用，放松类修改必须人类合并（单向棘轮）。SESG 的生产数据给出人类成本下界：每轮新威胁闭环人工约 2 小时。

### Insight 8 · 微观加速与宏观节奏之间存在实证鸿沟

同一时间窗内：Anthropic 内部人均产出 8 倍、OpenAI Sol 自动后训练 Luna、AlphaEvolve 参与下一代 TPU 设计——但 METR 多实验室试点（Anthropic/Google/Meta/OpenAI 参与）显示**没有公司报告研发整体节奏 2x 加速**（Anthropic 明确自认），无公司让 AI 做终审判断。METR 桌演给出半定量解释：speedup ∝ TH^0.39（时间视野 17 倍只换来约 3 倍提速）——执行趋近瞬时后，串行瓶颈转移到人类反馈、真实 ML 实验与外部评审（Amdahl 定律）。"AI 造 AI"完成了从宣言到实操的跨越，但复合式加速尚未在宏观数据中显形。

### Insight 9 · 算力-认知劳动替代弹性 σ 是宏观争论的单一关键参数

软件反馈闭环能否绕开算力瓶颈实现智能爆炸？2507.23181 用同一份面板数据（OpenAI/DeepMind/Anthropic/DeepSeek 2014-2024）算出两个相反结论：基线规格→强替代（RSI 不受算力约束）；含前沿实验规模的规格→σ≈0 强互补（认知劳动暴增也替代不了实验算力）。Epoch AI 的立场值得记录：这是少数可被受控实验裁决的 AGI 争论（随机分配研究者算力预算、测算法改进的外推性）。AI4AI-Bench 提供微观补充：即便算力管够，agent 在算法设计层也只走完不到 1/5 距离——短期内 σ 之争可能被"品味瓶颈"架空。

### Insight 10 · 测量基础设施本身正在成为一级瓶颈

PaperBench 榜首被 self-report 刷到 0.93（人类 PhD 基线的 2.2 倍）却零独立验证；METR 超过 16 小时的时间视野因任务饱和不可测；CORE-Bench 15 个月饱和；MirrorCode 未正式发布即被公开模型饱和。评估器瓶颈论的终极形态是"**人类失去出题能力**"——而这可能先于 AI 的能力天花板到来。BenchJack 的回应（基准 secure by design + 对抗式自修复管线把可 hack 任务从 100% 压到 10% 以下）催生了一个新物种：**自改进的基准**——评估基础设施自己也进入了 RSI 循环，这是"Red Queen 竞赛"的字面实现。

## 四、对六篇论文的重新定位（读完全部材料后的修正视角）

小红书原帖的分类（评估侧三篇/模型侧一篇/框架侧两篇）是准确的入口，但补上 WikiSkill、Weng、Anthropic 与 6-8 月动态后，更本质的分法是**按"冻结什么"分**：

| 论文 | 冻结的锚 | 进化的部分 | 锚的代价 |
|---|---|---|---|
| DGM | 整个评估器（SWE-bench）+ 探索循环 | agent 源码 | 评估器天花板，2 周/run |
| RQGM | epoch 内评估器 | agent + evaluator（跨 epoch） | epoch 边界的尺度跳变 |
| EvoLM | 锚定数据的判分精度约束 | rubric 生成器 + policy 权重 | 锚定集覆盖度 |
| WGtG | 人工锚定集（不参与进化） | 评估 metric + 技能 | 锚定集标注成本 |
| ECHO | GRPO 目标形式 | critic + policy 权重（同步） | 无结构化知识沉淀 |
| MOSS | 进化引擎 + 关键点集（循环内） | 底座 harness 源码 | 批次外回归盲区 |
| WikiSkill | 验证集 + 门控规则 | wiki（自由）+ 技能（门控） | 知识层污染无独立审计 |
| Continual Harness | 冻结 PRM / 教师 | harness 四组件 + 权重 | 能力地板；无种群多样性 |
| Meta-Harness | 外部 proposer + 搜索集 | harness 代码 | proposer 不进化；TB2 搜索=测试 |
| Self-Harness | 官方 verifier + 双 split | harness 配置面 | held-out 进晋升规则，锚变薄 |
| AutoSaddler | dev 集 + 反思 | prompt/tool/middleware | dev 被反复"选"，磨损 |
| EnvHarness | 原环境验证器（R 轴不暴露） | 环境接口层 | 环境会说谎；依赖 reset |
| MetaCaster | 真实数据 + MSE（元训练期） | 系统提示 + 技能库 | 部署期无锚 |
| Metan | 冻结 Ω + 外部基准 | Ω 的输入（轨迹 + 代码） | 深度 3–6 收敛；锚仍是基准 |
| Co-Harness | 验证集 + 归因分类法 | harness diff + 权重 | 数学域；两轮 |
| EvalCEGAR | 训练 split 碰撞对 | 算子池 | 需精确 oracle |
| RHO | **无**（自偏好） | Skills + Tools | 单轮；自偏好偏差 |

**每一家都在"冻结的锚"与"进化的自由度"之间做交换**——这就是 2026 年 RSI 研究的真实形状：不是"能不能自改进"（能），而是"锚定结构如何设计才能既保住可测性、又不把天花板钉死"。

## 五、开放问题（按可检验性排序）

1. **最小锚问题**：维持评估器不塌缩所需的人工锚定量的下界是多少？（WGtG 的锚定集、EvalCEGAR 的碰撞对给出两个数据点，无理论）
2. **品味可否被编译**：wiki/技能层能否沉淀"方向判断"而不只是"流程知识"？（WikiSkill 的 skill-impact 审计线索是雏形；Anthropic 的 64% 优于人类的下一步判断是内部指标）
3. **σ 之争的实验裁决**：随机分配算力预算的受控实验何时有人做？（Epoch 已给出实验设计）
4. **meta-depth 上限的普适性**：Metan 的 2.5 上限是否适用于"改输入"路线？涌现层级角色随深度持续分化还是同质化？
5. **跨代锚漂移**：RQGM 的 epoch 边界换尺、SESG 的 v0→v6 演化——锚本身的更新由谁验证？（目前答案都是"人类"，但没有协议化）
6. **RHO vs AutoSaddler 的裁决**：无锚 harness 优化多轮是否保持单调？RHO 的多轮实验将直接检验 insight 2；若单调，insight 2 改为"无锚不**可验证地**进化"。
7. **技能库 vs 条件化**：Metan 的 72/15 比例在技能进化场景是否成立？需要一个"检索到的技能作为 prompt 前缀 vs 作为可执行程序"的受控实验（Evo-Harness 的隔离框架是现成工具）。
8. **crossover 的可操作测量**：iCoder 的"逐步降低 prior 密度看性能何时崩"能否成为标准协议？
9. **宏观加速何时显形**：如果 2027 年 METR 仍测不到 2x 节奏加速，是 Amdahl 串行瓶颈成立，还是加速被"做更多实验"消化？两个假说的区分性预测是什么？

## 六、给从业者的三条行动建议

1. **建 harness 先建锚**：任何自改进循环上线前，先固定一小块不参与进化的评估资产（人工标注锚定集/蜜罐任务/隐藏碰撞对），并把"锚上性能不降"设为所有自动晋级的硬门。这是六篇论文收敛出的最便宜的保险。
2. **按层分配修改权限**：文本层（skill/prompt）给 agent 自主快环；源码层要求 propose-verify-promote 三段门控 + 回滚资产；权重层保持人类触发的慢环。MOSS 的四件套（版本/审计/预测/回滚）是源码层的最低配置。
3. **把失败也编译进知识层**：WikiSkill 的 skill-impact.md（被拒提案的 diff+原因永久留档）成本极低、收益直接——它让系统不重复失败，也是未来审计的原始凭证。
